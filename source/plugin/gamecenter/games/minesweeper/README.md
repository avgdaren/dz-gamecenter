# 天使扫雷 minesweeper

16 × 16 / 40 雷的单机扫雷，接在 gamecenter 平台下，有自己的服务端校验。
玩法、校验与视觉：**小蓝**；平台原作者 Carinoasd（`(C) 2026`）。

---

## 1. 规则

- 固定盘 **16 × 16，40 颗雷，216 个安全格**。没有难度选择：游戏中心一个 gkey 一条榜，分档会把榜冲散。
- 点开任意一格开始计时（**第一下周围九宫格保证没有雷**），翻开全部 216 个安全格即完成。
- 左键挖开、右键插旗；点已翻开的数字，如果周围旗数等于数字，会一次翻开其余邻格。
- 手机：长按插旗，或打开「插旗模式」点按插旗。
- 踩到雷本局结束，**提交成绩为 0 次**（不发成绩）。
- 得分 = 从首点到完成的毫秒数，**越短越好**（`game.json` 的 `order: asc`、`unit: 毫秒`）。
- 计时不暂停：切到后台、切走标签页都照常计时。

## 2. 盘面是「种子 + 首点」算出来的

`game.js` 与 `verify.php` 使用**同一套整数算法**，不依赖浮点、不依赖随机数实现：

1. `Park–Miller`：`s = s * 48271 % 2147483647`，初值 `s = seed`（平台 `api.start()` 发的 1…2147483646）。
2. 用部分 `Fisher–Yates` 从 `0..255` 里抽出 40 个雷位。
3. 若首点周围九宫格里有雷，按同一随机流把这些雷**挪到九宫格外的空格**（候选表按格号升序，取 `free[s % count]`，取走后用尾元素填洞）。
4. 服务端只信自己算出来的盘面，不信前端送来的雷位。

首点只是"决定盘面"的输入：若两个不同的首点恰好得到同一盘面，两次提交都算合法。

## 3. 提交格式（`api.submit` 第二个参数）

| 键 | 值 |
|---|---|
| `v` | 规则版本，`1` |
| `score` | 用时毫秒（整数） |
| `first` | 首个点开的格子，`0..255`（行优先） |
| `open` | 全部翻开的格子，逗号分隔，如 `0,1,2,…`（216 个） |

`verify.php` 的判定顺序：

1. 版本、字段、格式、长度（`open` ≤ 2000 字节）；
2. `score` 在 **3000 … 7200000** 毫秒之间；
3. `first` 在 `0..255`；
4. 用 `seed + first` 重算盘面；
5. `open` 必须**恰好 216 个、互不重复、且没有一个是雷** → 等价于"翻开了全部安全格"；
6. 通过后 `score` 用提交值，并返回 **`minms = score`**。

### `minms = score` 能挡什么、挡不住什么（重要）

平台会用「开局到交成绩的真实耗时」比对 `minms`：真实耗时低于 `minms × 0.85 − 1500` 就退回。
`minms` 取玩家申报的用时，于是：

- **能挡**「报得比实际慢」「秒开秒交」：申报 30 秒 → 真实耗时不到 24 秒就退回。
- **挡不住**「报得比实际快」：真玩 60 秒、申报 3 秒 → 后者的门槛只有 `3 × 0.85 − 1.5 = 1.05 秒`，真实耗时远超门槛，**照样通过**。

也就是说：**本版校验的是「完成集合」，不是「真实用时」**。
`score ≥ 3000 ms` 只是**申报值**的下限；平台那边的真实耗时门槛最低只有 **1050 ms**（申报 3000 ms 时），
不是「至少真的玩了 3 秒」。「防缩短成绩」要有服务端计时（平台记录开局时刻并计算 elapsed）；
当前 `verify($seed, $data)` 拿不到开局时间，属于平台侧改造，不在本版范围。

验收口径按此写：**「合法盘面 + 完成集合正确 + 申报用时 ≥ 3000 ms」**，
不写「伪造分数一律拒绝」，也不写「至少真的玩了 3 秒」。

## 4. 文件

```
game.json    名称、规则、单位、排序
game.js      前台：棋盘、计时、插旗、连开、键盘、手机长按、WebAudio 音效
style.css    淡蓝 / 米白 / 金线的「云上」视觉，含深色主题与响应式
verify.php   服务端重播校验（不读写数据库、不发积分）
icon.svg     大厅图标
tests/       JS/PHP 对拍与校验用例
```

## 5. 部署

1. 整个目录复制到 `source/plugin/gamecenter/games/minesweeper/`。
2. 后台 → 插件 → 游戏中心 → **重新扫描 games/ 文件夹**。
3. 新游戏默认不开放；管理员可先试玩。确认后勾「开放」并保存。
4. 后台把该游戏的 **分數上限保持 0（不限）**，否则超过上限的正常成绩会被平台退回。
5. 若发积分：`unit` 是「毫秒」，按分数发积分没有意义 → **请把 `ratio` 设为 0**，只做排行。

## 6. 自测

```bash
node --check game.js
php -l verify.php
node tests/check.mjs      # 可用 PHP_BIN 指定 php.exe
```

覆盖：10 组种子的 JS/PHP 雷位完全一致、200 组随机盘的雷数与首点九宫格不变量、
正常通关、含雷、漏格、重复、版本错、计时过短/过长/为 0、首点越界、非数字、超长、换盘首点。

## 7. 已知边界

- **成绩是客户端秒表**：服务端只校验「完成了哪些格」，不校验真实用时；
  `minms` 只能把「秒交」挡在 1050 ms 以上，缩短成绩拦不住。
- 固定盘无难度选择；要分档需要新增独立 gkey（各自的榜），本版没做。
- 音效由 Web Audio 实时合成，不听文件；各浏览器音色会有差异。
