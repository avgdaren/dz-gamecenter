# 好友五子棋 · v1a

作者：GPT / Codex；适配 gamecenter（原作者 Carinoasd，(C) 2026）。私有项目使用。

本目录不能单独复制给仍运行旧版插件的站点。五子棋同时依赖本次插件路由、房间服务和三张新表，必须按同一候选提交完整升级。

## 升级顺序

1. 在本地测试站备份现有插件及数据库，记录正在运行的提交/版本。
2. 部署本 PR 的完整插件改动：gamecenter.inc.php、install.php、元数据、视图/后台说明、新增 lib/room*.php 与 lib/gomoku.php、cron/ 和本目录。保持原有 memory、snake、SDK 文件。
3. 使用 Discuz 的插件升级入口执行 upgrade.php（它会包含 install.php）。版本元数据为 1.2.0；新增 gamecenter_room / room_member / room_action，全部 InnoDB；不会 ALTER 或清空旧六表。
4. 后台重新扫描，先由管理员预览，再开放 gomoku。单机积分/排行配置不作用于本阶段的房间结果。
5. 用两个不同账号访问 `plugin.php?id=gamecenter&mod=play&game=gomoku`，创建房间并分享邀请链接；普通账号参与时游戏必须开放。

插件 install/upgrade 只在论坛受保护的安装流程执行，不直接浏览 PHP 文件。未建表时房间 API 返回升级提示，不退回假单机模式。

## 数据与操作

- 服务端保存棋盘、轮次、截止时间、结果、版本与操作记录；前端只提交落子意图。
- 点棋盘预选，点击“确认落子”发送；认输有界面内二次确认；等待房间可取消。
- 刷新或重新打开同一账号时，通过会员指针恢复最近房间。不使用前端缓存棋盘作裁决。
- 网络未确认时保留请求 ID；再次确认用同一 ID/版本重放。不同 ID 的同回合请求仍只接受一次。
- 每回合 60 秒，等待加入 5 分钟；计时展示不代表本地判负。安静时段的过期在恢复访问后按服务端时间处理。
- 创建请求有界清理到期房间；可选调度入口 `cron/room_cleanup.php` 每轮最多处理 50 个。v1a 保留历史，不自动删对局。
- 三张新表必须在同一事务连接，不能分别映射到不同数据库连接。

## 回退

先关闭 gomoku，恢复备份的旧版插件代码与对应版本元数据；停止本次可选的清理调度。新增房间表作为已知、可备份的附加 schema 保留，保存候选版对局，不影响旧版六表。确认旧游戏正常后再结束回退。

不要导入结构快照或直接 DROP 表；如确需恢复数据库，使用事前备份并明确处理升级后新增的对局数据。卸载整个插件会按现有插件卸载流程删除其表，包含本次新增三表。
