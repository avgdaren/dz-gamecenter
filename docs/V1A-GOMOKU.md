# v1a 五子棋 · 实现契约

作者：GPT / Codex；2026-10-26；Issue #6。已同步 main `6f9d080`，按 PLAN §三实现；memory 2.0.2 与美术资源保持 main 原样。

## 范围

15×15 自由五子棋，连五及以上获胜，无禁手；房主执黑，第二人加入后开局。支持房间号/邀请链接、认输、满盘和棋、刷新恢复。等待 5 分钟过期，每回合 60 秒，服务端时间裁决。

本阶段保存对局结果及最近记录，不发积分、不写单机成绩/最高分榜。AI、匹配、观战、聊天、悔棋仍不包含。现有单机 SDK 不变。

## 存储与一致性

- `gamecenter_room`：房间号、双方 UID、225 格棋盘、状态、轮次、结果、版本、截止时间、最后落子、创建请求标识。
- `gamecenter_room_member`：每 UID 一行，指向最近房间，防止同一账号并发创建/加入多个活动房间。终局不删除指针，新一局时覆盖。
- `gamecenter_room_action`：按 room/UID/request_id 唯一，保存请求指纹和生效版本；重试返回当前状态与原生效版本，同 ID 不同请求拒绝。

变更在 InnoDB 事务内，房间行 `FOR UPDATE` 串行裁决。锁内获取服务端时间，再处理过期、版本、回合、格子和判胜。过期判负与有效落子互斥。1213/1205/创建房间号碰撞有限重试，失败不向玩家暴露 SQL。事务内锁等待最多 2 秒，结束后恢复原 session 设置。

会话锁等待通过 `SHOW SESSION VARIABLES LIKE 'innodb_lock_wait_timeout'` 读取，兼容 Discuz 默认 querysafe；不使用会被拦截的 `SELECT @@SESSION...`。读不到合法值则停止事务，保留安全检查。

创建/加入先锁会员指针，再锁已有房间及目标房间；落子只锁房间，不反向锁会员指针。重复创建请求有唯一键，可在终局后恢复原请求结果。无网络成功确认时，前端保留同一请求 ID 供玩家重试，不生成第二次落子。

每账号 10 分钟最多新建 30 个房间，重放同一创建请求不计为新建。三张房间表在事务开始前校验使用同一物理连接；拒绝把它们映射到不同连接。

等待房间和活动对局按请求访问时裁决过期；创建时有界清理少量过期房间。额外提供插件内清理入口供 Discuz 调度。无人访问时不承诺恰好在截止毫秒执行任务；恢复访问后结果由截止时间决定。v1a 保留已结束记录，不自动删除历史。

## 新增接口

`POST plugin.php?id=gamecenter&game=gomoku&op=room&inajax=1`。沿用论坛会话、POST 和 formhash；服务端从 `$_G` 取 UID，拒绝游客/无参与权限用户。房间状态仅双方可读，房间号不是权限凭据。

| action | 参数 | 作用 |
| --- | --- | --- |
| current | 无 | 恢复账号当前/最近房间 |
| create | request_id | 幂等创建；有活动房间时返回原房间 |
| join | room | 加入等待房间；同 UID 不能占双座 |
| state | room | 读取、处理到期，返回权威快照 |
| move | room/version/request_id/cell | 带版本与请求 ID 落子，cell 为 0～224 |
| resign | room/version/request_id | 认输；等待状态房主取消 |
| history | 无 | 本人最近 10 个已结束/取消房间 |

响应含 `ok/code/msg/server_ms/room`，快照含 `version/status/board/turn/deadline_ms/black/white/winner/reason/last_cell`。错误不回显内部异常。非房间成员拿不到快照。gomoku 的旧 start/submit 路径明确拒绝，避免伪造单机分数。

## 前台

2 秒 + 小幅错峰轮询，正常间隔 ≥1.5 秒；错误指数退避至 15 秒；页面隐藏停止轮询，恢复立即同步；同一页面任何时刻最多一个请求。使用 AbortController 限时请求。倒计时按服务端时间校准，只显示，不能在本地直接判负。

落子先选点、预览，再点一次确认，减少手机误触；棋盘按整数格渲染，前端不推断输赢。邀请链接只含房间号，成员登录后主动加入；终局显示结果，支持创建下一局及最近记录。离线不抹棋盘，不把未确认请求当成功；重试沿用请求 ID。

## 升级与回退

新增表统一由插件 install/upgrade 创建，可重复执行。插件版本升至 1.2.0，游戏资源版本 0.1.0；卸载清单同步新增表。现有六表不改，memory/snake 资源不改。

部署需先备份插件及数据库，后台升级建表，再扫描/开放 gomoku。旧版回退先关闭 gomoku，恢复原插件文件，保留新表以保存候选版记录；不导入含 DROP 的结构快照。正式论坛发布在本地验收之后单独进行。

已完成 1.2.0 升级的测试站，本次 querysafe 修复无需再次建表；部署最新候选代码并清除临时异常回显。候选分支已包含 main `6f9d080` 的 memory 2.0.2，禁止用旧候选包覆盖其美术资源。
