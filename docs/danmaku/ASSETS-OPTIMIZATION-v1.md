## 排查与取舍

本机论坛的两个难度已经复用同一游戏目录，但切换使用完整页面导航，仍需重新解析脚本和准备声音。`bgm-bank.js`约8.86MB，包含Base64音频；旧音频管理器首次交互会等待整套音库解码。两关v8还在第一次开始时同时准备两关音库。仅缩小图片不能解决这些等待。

美术原件不覆盖。29张不同图片由25,508,598降至19,732,379字节，最终减少约22.6%。其中19张战斗图、动作／弹体取样素材保留PNG路径，仅无损重压IDAT；其他大图用`cwebp 1.6.0 -z 9 -exact`，保留尺寸、Alpha与ICC。参见[官方无损／exact参数说明](https://developers.google.com/speed/webp/docs/cwebp)。没有缩尺寸、减色、JPEG或近似无损处理。

最初全用WebP可少约32%，但实际浏览器缩放／取样出现差异，故保留了相关PNG。最终29张逐一解码RGBA哈希均与原图一致；两关实际宣告画面比较，PNG／WebP合成路径的最大通道舍入差为1／2（8位通道），不是整张画布逐像素相同，不把它写成0差异。角色身份、透明边缘、布局和素材内容保持，截图已查看。记录见[资源清单](assets-lossless-v1/MANIFEST.json)。

BGM本身已经是MP3，再降低码率重编码不能承诺无损。本轮保留当前运行音乐的每个原字节：论坛BGM由Base64脚本改为751字节的清单＋6,644,547字节的原MP3；无需把约33%的Base64表示膨胀带入脚本解析。原始音乐／图像和已有配乐剪辑保持，没有新剪辑、变调、降采样或二次有损编码。

## 加载与缓存

新增`source/plugin/gamecenter/games/_danmaku_assets_v1/audio-lazy-v1.js`，沿用原音乐计划、循环点、音效事件与混音，只改资源准备：

- 首次只等待当前曲；默认关闭的音效不参与启动解码。后续Boss曲后台预备，不阻塞开始。
- URL音频原始字节缓存上限24MiB，解码按素材对象／采样率合并并发，资源失败可退化为静音，取消／释放后的旧任务不能复活播放。
- 两关只解锁备用音频上下文；第一关最终阶段预备第二关道中曲，切关释放前一关上下文／缓冲，保留原逻辑音乐偏移。
- Easy／Normal继续分别gkey与榜单，共用内容哈希资源URL，文件名依据最终编码字节SHA生成。入口脚本提前捕获自身URL，两个game.json版本同步至0.2.2；资源版本更新不依赖回调时的`document.currentScript`。

论坛部署需由平台维护者同步缓存策略：仅哈希图片／MP3使用`Cache-Control: public, max-age=31536000, immutable`；两个入口和运行脚本按版本更新。保留旧PNG兼容仍打开的旧页面，不用删除式同步覆盖整个平台。具体文件、SHA基线与操作见交付README。未部署前，线上用户不会自动获得这些优化。

## 检查与边界

[完整报告](assets-optimization-v1-validation.json)。本地HTTP服务对压缩前后使用相同静态缓存条件、未启用HTTP gzip：

| 检查 | 结果 |
|---|---|
| 冷标题页静态传输 | 14.85→4.32MB，约−71%；标题页不下载MP3 |
| 初次原生交互 | 只解码当前BGM，实际音频输出非零 |
| 热切Normal | 共用大素材／MP3新增请求0；仅约22.6KB包装文件 |
| 两关音频 | 备用关卡未提前整库解码；第二关曲能接续，旧关上下文和缓冲释放 |
| 美术 | 最终29张RGBA同原图；19张保留PNG采样路径 |
| 规则 | 两关定点会话快照同v8；论坛规则、回放、计分与校验PHP保持 |
| 界面 | 两关实际画面与原样式对照、暂停／失焦及原生声音检查 |

浏览器无脚本异常、资源404；8组音频准备／缓存／错误／取消边界通过。论坛game.json除版本外字段一致，gkey、api.start／submit及成绩字段未改；HTTP审阅使用本地SDK替身，不调用真实凭证／成绩接口。

本地约0.5秒首曲准备、0.2秒热Normal准备仅为本机无网络限速测值，不承诺线上耗时；若线上已有HTTP压缩，传输降幅也需重新测量。没有自然整关通关、真实手机／线上部署验收或新难度标定。
