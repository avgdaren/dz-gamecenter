## 音乐与发弹

沿用用户提供的道中《ヘクサフュージョン》和 Boss《残响》，MP3 与运行 BGM bank 字节不变。使用 FFmpeg 解码既有母带，通过 10ms 能量上升点估计节拍；作者据此选用道中约168 BPM、Boss约144 BPM的网格，将网格吸附至45ms内的实际起音点，再量化成60Hz整数步。未做真人听辨验收，这些是信号分析与编排结果。

199个道中拍点、1040个Boss半拍点已冻结在 `rules.json/hard01`，音源SHA和时间表见 [hard-v1-cues.json](audio/hard-v1-cues.json)。不在游戏中实时分析声音；关闭音乐、静音或音频不可用时，规则仍按同一时刻运行。暂停停止逻辑步，音乐沿现有管理器恢复位置。

| 部分 | 编排 |
|---|---|
| 道中 | 40只敌人的出场和全部射击吸附到道中拍点；原路径和补给保留。展开扇形、双侧交叉与精英多层扇，发弹前30步蓄光；基于能量的疏密分段用于Boss，道中按既有编队空档留出回收时间。 |
| Ⅰ 重拍双螺旋 | 每两拍开主环，强段半拍补慢环；下一拍双侧扇织入。缺口缓慢左右迁移，较弱段只保留主环。 |
| Ⅱ 切分追响 | 四拍一组，先锁定再三连针束，后半组侧向切入；较弱段减少追击与侧射。锁定后方向固定，刚转入阶段且没有预告的针束不发射。 |
| Ⅲ 逐拍星廊 | 六排星墙逐拍推进，门逐层移动；后两拍交叉扇作收句，较弱段减半星墙。门宽和每拍位移按低速移动预算留路。 |

Boss音乐在登场时从0开始，三阶段与两次转场共用一个 `musicTick`；阶段击破不会重启曲子或节拍。按原音源204.71s结束、1.5s续接的循环方式预排后续拍点，覆盖整个217s的Boss最长预算。转场中不发弹，恢复战斗后取当前乐曲的下一拍。三种弹型随玩家击破进入，音乐本身的段落不会强制改变Boss血条。

## 不计排行榜的范围

本页没有论坛 `api.start`／`api.submit` 请求，Hard只生成本地分数与回放。`hard01.ranked=false`，JS `rankedRules` 和 PHP `RANKED_RULES` 的当前计榜列表仅含最新Easy／Normal；`SUPPORTED`包括Hard是为了本地复验，不能拿它充当榜单白名单。旧桥接也拒绝Hard规则。

论坛适配方将来同步时，Hard应绕过成绩提交与奖励路径，服务端从可信难度白名单拒绝Hard进入排行榜；不能相信客户端自报 `ranked`，也不能把Hard改标为Normal。未改既有SDK载荷或DB结构。本轮没有验证已安装论坛的HTTP接口、排行榜或奖励路径。
