## 制作顺序与交付

### 1. 先解决第二关战斗角色的辨识度

围绕实际战场尺寸，重做或整理两个人形小怪与铃羽的战斗图：明确轮廓、发色／服装主色块、武器与身体的关系，减少缩小后糊在一起的装饰。保留既有人设与大立绘；不把高细节源图直接缩小加变形当成正式动作素材。

先交实际显示尺寸的静态对照和短动作预览，再放进真实弹幕、庭院背景检查。补充待机、移动、施法所需的少量清楚动作；原尺寸可辨认后再扩展。非人形花铃守卫按实际问题决定是否调整，不默认全部重画。

完成依据：两个人形小怪彼此可辨，铃羽身体、铃杖与施法方向清楚，动作稳定，敌弹叠加后仍能看懂。图像与绘制调整不顺带改变碰撞半径、敌人路线、HP或攻击编排。

### 2. 补齐铃羽演出，并穿插优化花叶弹体的融合

将入场、待机／移动、施法前后动作、阶段转换、击破与退场连成完整表现。三个阶段分别体现风流、花瓣与铃声回响，强调动作和实际出弹来源的对应，不只叠加光圈和文字。

演出模板共用不要求招数沿用第一关。风流、花瓣与铃声应形成各自的空间控制和躲避方式；弹幕形状、来源、变化方式、出手组合及阶段时长围绕本关需要设计，再配相应动作与提示。当前近似第一关的攻击和HP不作为必须保留项。

花瓣、叶片、铃花继续沿用已认可的造型方向；把角色动作、发射位置、短暂发射痕迹及弹体展开协调起来，检查实战违和感和判定辨识。演出不能遮住通路与自机判定点。

保留已确认的场景节奏：道中4.9单位／秒；Boss登场停6.5秒，再用2.5秒平滑恢复至2.45单位／秒。先在现有时间窗口内补表现；不因加演出自行延长无操作等待或改动战斗时间轴。

交付：可定位查看入场、三个阶段与退场的第二关表现候选，供用户检查观感；局部表现检查不代替真人难度验收。

### 3. 把第一关与第二关接成同一局

从本计划起预留统一关卡调度，前两步保留清楚的关卡结束和进入接口，正式连续试玩在本步交付。

当前第一关的胜利会进入单关最终结算，第二关则自行初始化资源；整合需要新的整局流程，不能只把两个页面放进同一个压缩包。

| 项目 | 本步落实的行为 |
|---|---|
| 统一主入口 | 同一个标题、难度入口、操作设置与音量设置；主流程从第一关开始，第一／第二关及Boss练习另作明确入口 |
| 关间衔接 | 第一关击破、放行与短转场后进入花庭；场景、关名、BGM交接自然，第一关完成提示不再结束整局 |
| 资源继承 | 生命、原始火力值、B库存按实带入第二关；补给仅来自明确的现有规则，不偷偷重置成练习资源；冷却、无敌状态等跨关时间基准正确转换 |
| 清场与统计 | 关尾掉落只处理一次；上一关敌弹、自机弹及临时效果不泄漏到下一关。第一关统计归档，第二关从独立关内统计开始，整局累计分数与记录不重复累加；第二关草稿计分另行核对，不直接套第一关通关奖励公式 |
| 失败与重试 | 重新开始整局回到第一关初始资源；第二关／Boss重试使用各自抵达时的检查点，不能刷取过关奖励；使用练习、重试或测试辅助的局保留清楚标记，与一次连续完成的记录区分 |
| 完成与返回 | 第二关结束后统一显示两关进度和分项／累计结果，可返回标题、重开整局或进入练习 |
| 难度与兼容 | 接续第一关选定的难度与通用规则；明确第二关各档对应的实际编排。当前只有一套草稿，不直接把它标成Easy／Normal／Hard全部完成；档位编排未补齐时如实标注测试范围 |

对白接口可以先用待改草稿或简短过场接通，不能因台词未定阻塞资源与关卡流程，也不提前把草稿写成已确认剧情。第二关延续追寻前辈的主线，不自行补完真相。

交付：一个能从第一关连续进入第二关的离线试玩件，保留旧单关基线与练习能力。此时若仅完成离线流程，不声称正式排行榜或服务器回放已经支持整局。

### 4. 文案确定后，统一两关对白与立绘呈现

本项先等文案收敛；可以独立于前述美术、演出和串关工作讨论。依据 [已确认主线](STORY-v1.md)，整理第一关放行、主角前往花庭、铃羽交战原因及战后线索的衔接，避免两个独立试玩的开场／结束信息重复。

文案确定后再实施用户参考的形式：通过立绘显示／突出当前说话者，文字与角色同步切换，提供继续与跳过；对白期间正确冻结战斗、输入和音乐时间。沿用现有人设，不照搬参考图中的人物或台词。

交付：文案与说话者对应清楚、两关接续自然的剧情版本。暂缓对白不会被误写为用户取消了对白要求。

### 5. 按串关实际资源调整第二关节奏与难度

用第一关实际抵达时的生命、火力和B库存检查第二关，覆盖低火力、有损耗及正常成长等有代表性的情况；不能继续只拿满资源的独立练习判断压力。沿统一难度入口整理第二关相应编排与补给，调整有反馈或证据的问题。

本项的继承资源分析提前用于下一轮第二关战斗调整，不等到末轮才发现成长后压力消失；正式串关交付仍在第三步。先按正常成长状态检查成组敌人能否出手、重点目标存活时间与Boss阶段长度，再根据场景和角色职责重排数量、密度、交错和招数。低火力状态检查恢复机会，不能因此让正常继承火力下全段被瞬间清空；也不靠全体等比加血抵消成长。对照记录保留第一关数据作为参照，不要求数量、弹峰、HP或相同资源下的击破时间逐项相等。

检查两关总时长、第一关收尾到第二关开场的起伏、第二关三个阶段的差异及音乐衔接。花叶弹体的实战融合、敌我辨识和亮背景可读性贯穿前面各步，到这里统一复核。

真人连玩、手感与难度由avg达人反馈。小典做新增功能的语法、定点状态转换、继承／重试边界、必要回放和打包检查；不默认进行整关自动自然通关，也不为凑制作轮次改动已确认的第一关难度。

### 6. 收成两关统一交付，并明确正式接入的边界

整理同一入口的离线包、操作说明、素材与音乐署名、版本清单及回退基线。检查无外部资源依赖、暂停／失焦、设置继承、桌面与窄屏布局；性能检查按实际新增绘制和资源负载安排，不把模拟窄屏写成真实手机验收。

整局规则与成绩格式使用独立版本，不覆盖已有第一关规则和历史回放；两关资源继承、统计、关卡事件与输入时间线需要能够确定性复验。正式接入现有论坛／排行榜时，再同步第二关与整局的JS／PHP校验、时长／载荷上限和成绩合法性，验证正常记录通过、非法记录被拒绝，并复核变长后的服务端重算成本。离线两关交付与正式平台接入分别记录完成状态，不能因前者可玩就声称后者完成。

不改现有插件对外接口，不在本轮规划中执行上传、合并或部署。
