# 天使弹幕祭 · v0.1 开发规划

日期：2026-11-10（北京时间）
规划：小典 / Codex；服务于 avg达人 的天使动漫游戏中心。
状态：规划稿。尚未实现、试玩、压测或上架；本文中的参数均为首轮开发候选，不代表实测结果。

后续已细化为 [P0 详细规格 v0.2](天使弹幕祭-P0详细规格-v0.2.md) 与 [参数草案](天使弹幕祭-P0参数草案-v0.2.json)，具体时点、回放编码和参数以详细规格为准。

## 1. 产品定案

做一款浏览器点开即玩的竖版弹幕射击游戏：自动射击、移动躲弹、有限清屏技能，直接挑战一个三阶段 Boss。

目标体验：第一次打开就能操作；看得懂子弹路线；失误后知道哪里躲错；熟练以后愿意追求无伤和高分。单人即可获得完整体验。

首版目标一局约 3～4 分钟。每阶段最多 70 秒，击破后进入下一阶段；超时或生命耗尽即失败。开场及转场合计不超过 10 秒，整局逻辑硬上限 220 秒。实际平均时长与难度须经试玩调整。

暂定名称《天使弹幕祭》，游戏识别码 `danmaku`；实施前在最新完整源码与后台确认名称、识别码未占用。

## 2. 首版范围

| 项目 | 首版内容 |
|---|---|
| 自机 | 1 个角色，1 种固定武器，自动向上射击 |
| 敌人 | 1 个原创 Boss，3 个阶段，无前置杂兵关 |
| 弹型 | 旋转花瓣、定向连射、交错波浪，末阶段按固定节奏组合 |
| 生存资源 | 3 条生命、2 次清屏；不掉补给，不因失误补充清屏 |
| 游戏模式 | 标准计分；辅助练习不入榜 |
| 操作 | 桌面键盘、手机触控；均遵守同一移动速度上限 |
| 成绩 | 沿用游戏中心日／周／总榜，只有标准模式进入这些榜 |
| 表现 | 1 套背景、自机与 Boss 素材、必要音效、1 首本地 BGM |

暂缓内容：多人联机、装备与随机词条、角色养成、角色商店、多武器、多 Boss、每日挑战、幽灵挑战、服务器续局存档。先完成一个可反复玩的 Boss，再考虑扩展。

前面讨论的“两档难度”在首版落成“标准 + 辅助练习”。练习增加容错，用于学习路线；正式榜始终只有一套规则，避免不同难度混榜。普通日榜与“每日挑战”是两种功能，首版仅接前者。

## 3. 操作与生存规则

- 方向键或 WASD 移动；Shift 按住慢速移动并强化判定点显示；X 或空格释放清屏；Esc 暂停。
- 全程自动射击。移动斜向归一化，不能比横向更快；离开游戏区域、输入框聚焦时不拦截页面快捷键。
- 桌面正常／慢速移动候选为每秒 240／90 逻辑像素（按详细稿调整）；在 480×640 的逻辑场地内统一计算。
- 手机使用相对拖动，手指可落在角色旁边，避免挡住判定点；设慢速开关与清屏按钮。按每个逻辑步的速度上限移动，手指跳动不能让角色瞬移。
- 自机判定半径候选为 3 逻辑像素；角色中心常显判定点。敌弹的有效区域落在清晰可见的实体内，柔光不计入碰撞。
- 被击中扣 1 命，不立即清除全部敌弹；给予 2 秒无敌并消除判定点附近的危险弹，避免复活连撞。无敌期间不能获得擦弹分。
- 清屏立即消除当前敌弹并提供 1.5 秒无敌，不造成 Boss 伤害；按键按下沿触发，长按不会消耗两次。首版不做中弹后的补救窗口。
- 每颗敌弹首次进入擦弹范围且没有命中时，记一次擦弹；同一颗弹不能反复刷分。阶段结束、清屏、复活消弹不产生擦弹分。
- 切到后台、窗口失焦、触控中断时自动暂停并清空输入；回到游戏后点击继续，经过短倒计时再恢复。暂停不推进弹幕、计时或得分。

同一步发生多个事件时统一按以下优先级处理：先应用输入、移动和生成／推进子弹，再应用清屏及其无敌；然后判定自机命中，生命归零立即失败，不计该步 Boss 击破；仍存活时再结算输出与阶段击破。阶段击破清场优先于擦弹和超时，截止步击破有效；未击破才判超时。没有结束或转场的步才结算擦弹。即“清屏能挡住当步命中，同归于尽判失败”，界面说明与两端实现须一致。

练习可降低弹速、增加生命、选择阶段、显示死亡瞬间位置，使用独立本地结果面板，不提交成绩。平台游戏页仍遵守开局契约；普通练习通过 `api.start()` 开局，但不调用 `api.submit()`，不进入榜单。未来带 daily／ghost 的入口须强制标准规则，不允许消耗挑战次数后改成练习。

## 4. 三阶段战斗编排

阶段名称为工作名，具体人物、美术和台词在可玩原型验收后定稿。

| 阶段 | 弹幕与学习目标 | 必须满足的公平性要求 |
|---|---|---|
| 一：星环 | 缓慢旋转的花瓣弹，留较宽缺口；学习小判定与慢速微调 | 开场有准备时间；第一轮不以玩家出生点封路 |
| 二：星雨 | 瞄准玩家当前位置的连射，与宽间隔波浪交替；学习诱导后离开原位 | 瞄准方向发射后锁定；危险波次前给清楚的蓄力提示 |
| 三：星幕 | 复用花瓣与波浪，在固定时点穿插定向连射；学习边观察边换位 | 不能靠叠加堵死所有出口；高压段后有恢复节奏 |

每阶段有独立血条，击破即清除场上敌弹，短转场后重置下阶段血条。超时判失败，不能靠拖延直接跳阶段。Boss 保持在可射击区域，只做清楚可读的横向移动。

标准模式使用固定编排和参数，同一输入必须得到同一结果；首版不随机改变弹速、缺口和难度。每阶段以正常追踪射击约 50～60 秒击破作为首轮调参方向，不把这个估计写成已验证时长。

先分别验证三个弹型，再做组合。难度主要调整弹速、缺口、发射间隔和组合时机；不靠突然提高 Boss 血量堆时长。

## 5. 计分与结束规则

计分原则：通关优先，之后奖励操作质量；擦弹是加分选择，稳健躲避也能通关。

候选计分公式：

`总分 = 通关奖励 + 阶段击破分 + 有效伤害分 + 擦弹分 + 通关剩余资源分 + 通关时间分`

| 项目 | 候选规则 |
|---|---|
| 通关奖励 | 击破第三阶段后 +200,000 |
| 阶段击破 | 每个阶段 +20,000，最多 60,000 |
| 有效伤害 | 将累计有效伤害按总 Boss 血量归一为最多 20,000 分；不算溢出和无敌目标伤害 |
| 擦弹 | 每颗合格敌弹 +10，最多计 1,000 颗，即 10,000 分 |
| 通关剩余资源 | 每条剩余生命 +2,000、每次剩余清屏 +1,000，合计最多 8,000 |
| 通关时间 | 按有效战斗耗时换算，范围 0～10,000；暂停不影响，换算常量在规则冻结时固定 |

理论总分上限 308,000。未通关不发通关、剩余资源或时间奖励，分数必低于任意合法通关局。清屏不会扣掉已经取得的分数，但会减少剩余资源奖励。

生命耗尽、阶段超时、通关为自然终局，可以提交标准成绩。主动退出和刷新视为放弃，不生成伪造终局或继续交成绩；重新开局使用新凭证。终局后停止逻辑，只提交一次；平台提示网络错误时保留结果和原始记录，不自动开始新局或反复提交。

结果页显示通关／失败、到达阶段、分数构成、命中次数、擦弹数、使用清屏次数和有效战斗用时，提供明确的再玩入口。标准成绩仍使用平台结果窗口，详细信息在游戏区域保留，不修改公共 SDK。

## 6. 画面与声音

- 竖版战场使用暗色星空背景；敌弹、玩家子弹、判定点三者轮廓和亮度有区别，不能只靠颜色区分。
- Boss 立绘不压在主要躲避区域；血条、阶段、剩余时间、生命与清屏数固定在场外或顶部安全区域。
- 敌弹本体优先清晰，粒子、光晕和震屏服从可读性；低特效只改变表现，不改变弹型、判定或分数。
- 桌面战场居中并限制高度，手机按容器等比缩放；至少核验 360px 宽布局。缩小显示不改变逻辑场地和游戏规则。
- 音效默认关闭，BGM 独立开关；用户交互后播放，暂停与终局同步处理。素材随游戏本地提供并记录来源及使用许可。
- 原型全部使用几何占位，不先做大量立绘、动画或正式音轨。

## 7. 技术接入与前置验证

已只读核对本地 `dz-gamecenter-handoff` 的 AGENTS.md、DEVELOP.md、gc.js、core.php 及现有 verify 示例。检出分支为 `feat/aquarium-v2`，HEAD 为 `4dc9e96`；源码游戏目录少于用户截图中的 18 款，因此它只能证明现有接口能力，不能代表线上完整版本。实施前重新核对最新完整基线。

遵循仓库约束：原生 JavaScript + PHP，不引入 npm、构建工具或 CDN，不改 Discuz 核心和公共 `api.start`／`api.submit`／manifest 契约。正常情况下新增 `games/danmaku/` 即可接入，不新增数据库表；以实施时核对结果为准。开发按一条 Issue、一个分支、一个 PR 执行。

推荐文件职责：`game.json` 负责登记，`game.js` 负责界面和输入，独立 JS 逻辑文件负责确定性模拟，`rules.json` 存版本化弹型参数和方向表，`verify.php` 做重播校验，`style.css` 与 `assets/` 提供本地表现资源。新增运行文件保留原作者 Carinoasd 版权并注明适配作者。

### 7.1 先证明能重播，再加美术

- Canvas 2D 渲染；固定 60 逻辑步／秒，画面绘制与逻辑更新分离，渲染帧率不参与计分。
- JS 与 PHP 使用一致的整数定点、方向表、更新顺序和碰撞规则；避免运行时浮点三角函数造成跨语言分歧。中间运算须保持在 JS 安全整数范围内。
- 碰撞要覆盖子弹和玩家在一个逻辑步内的运动，防止高速交错漏判；命中、清屏、阶段结束、擦弹的先后顺序固定，并通过边界样例复核。
- 回放记录规则版本、逻辑终点和合法输入，不信任客户端上报的位置、生命、Boss 血量或分数；PHP 自行重算终局、分数和统计。
- 总步数最多 13,200；敌弹同时存在数量候选上限 360，子弹寿命与出生次数均设上限。正常编排必须低于上限，不能在不同性能设备上随机少出弹。
- 输入采用紧凑、有界编码；包含最坏逐帧触控变化的合法满局，整个提交目标不超过 256 KiB。必须先证明正常局装得下，再启用校验上限。
- 解码前检查字节数，模拟前检查版本、步数、事件数、时间顺序和输入范围；超限及时拒绝。服务端不做实时逐帧轮询，只在开局与结算访问游戏接口。
- 规则版本更新时明确拒绝不兼容旧局并提示刷新，不能把版本不兼容描述为玩家作弊。

### 7.2 性能门槛

P0 先测正常单项记录，以及有最高弹量／最长逻辑步数的非合法标准局压力夹具；最长合法完整局在 P1 补验。初始预算目标：在约定测试机上，50 次最重重播的 p95 不超过 500ms；记录峰值内存并区分夹具种类。论坛配置按仓库记录的 4 个 PHP worker 核验，最终以测试环境实际配置为准。

集成后补测 4 路同时提交与同期普通论坛页面请求。记录普通页基线及提交期间 p95，初始目标是增幅不超过 300ms；明确测试硬件、页面、请求节奏与样本数。这是待测预算，不是容量承诺或线上结果。

若超过预算，先减少弹幕总量、缩短记录或优化逻辑，再复测；不能为了赶上架仅相信客户端分数。确定性重播能防伪分和非法位移，不能保证识别按合法规则运行的自动躲弹脚本。首版积分、周榜奖励均设为 0。

### 7.3 平台功能开关

首版 manifest 保持 `replay: false`，因此不开每日／幽灵挑战；是否具有 verify.php 与是否开放挑战是两回事。标准模式仍可通过 verify.php 后进入现有普通排行榜。后续启用 `replay: true` 前，须完成幽灵画面、同种子挑战及每日次数的接入验收，不能只改开关。

## 8. 开发阶段与交付门槛

| 阶段 | 实际交付 | 进入下一阶段的条件 |
|---|---|---|
| P0：玩法与重播原型 | 几何自机／Boss、三种独立弹型、移动／慢速／命中／清屏／暂停、最重样本的 JS/PHP 回放 | 真实浏览器能玩；同输入跨语言结果一致；碰撞边界成立；重播与输入体积满足预算 |
| P1：完整可玩战斗 | 三阶段编排、标准／练习、计分、完整胜负与再玩、触控与容器布局 | 用户能完整试玩；基础弹型能读懂，出现的封路问题已修；首次／熟练体验分别记录，不能用模型代替真人难度 |
| P2：平台接入 | 开局／校验／提交／榜单、游客、规则版本、频率限制、终局与提交失败反馈 | 正常局不误拒；非法分数与非法输入被拒；重复请求仅一次生效；4 路提交负载检查通过 |
| P3：表现与发布候选 | 正式素材、音效／BGM、低特效、浏览器及窄屏回归、部署／回退说明 | 美术不遮挡弹幕；真实试听与实际操作已验；候选版本、通过项和未验项逐项写清 |

每阶段提供可运行交付和实际验证结果。P0 先交“好不好躲、重播跑不跑得动”，P1 再交完整战斗；在这两步成立前不扩大角色或内容数量。不按未经验证的天数承诺交付日期。

## 9. 必须覆盖的验收

1. 真实游玩：完整通关、第三次命中失败、阶段超时、各阶段转场、清屏与最后一击同帧、最后一命与击破同帧，均符合第 3 节的优先级。
2. 输入与暂停：斜向速度、慢速切换、长按清屏、失焦卡键、后台恢复、触控中断、页面滚动／输入框不受干扰。
3. 判定与计分：擦弹只算一次；无敌／消弹不刷分；越界子弹回收；失败分低于通关；资源和计时不会因暂停重复累计。
4. 跨语言验证：固定回放逐阶段比对，加随机合法输入差分；真实完整游玩记录也要通过 PHP。模拟通过与真人手感分别报告。
5. 非法提交：修改分数、生命／伤害伪值、瞬移输入、无效版本、乱序／超长记录、缺失终局、提前／加速提交，不能污染成绩。
6. 集成：游客可玩不记分；练习无提交且不入榜；重复提交只落一次；失败请求提示准确；后台扫描默认未开放；现有游戏入口与榜单冒烟不退化。
7. 表现与性能：实际桌面浏览器操作与录帧、360px 布局、实际手机触控、低特效、真实音频播放；实测最重合法回放与论坛混合负载。未做的明确标“未验证”。

## 10. 实施开始前与后续扩展

下一步是 P0，不是直接制作完整正式版。先核对最新完整源码与站点接入条件，建立对应 Issue 和独立分支，制作几何可玩原型与同步重播样本；本轮规划文件保存在工作区 output，没有写入现有水族馆分支。

首版完成以后，优先观察真实反馈中的弹幕可读性、首次到达阶段、重复游玩意愿和触控体验，再决定第二个 Boss 或每日挑战。首版不额外建设玩家行为采集系统，也不凭少量试玩宣称稳定通关率。

上线候选应给出所需文件、后台扫描／开放步骤、零奖励设置、资源缓存版本及回退办法。预计无数据库结构升级；关闭新游戏即可停止入口，完整回退须核验文件与后台登记状态，保留已有玩家成绩。
