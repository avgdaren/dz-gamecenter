## 1. 已实现的行为

- 论坛登录、用户组权限及POST/formhash；单人直接开战，双人创建五分钟邀请房间，好友明确点击“加入并开战”才占座。
- 每位账号只控制自己的席位；队友的生命、恢复余次和已锁行动可见。生命/胜负由PHP规则决定，前台没有扣血或结算分支。
- 存活成员确认齐后结算；否则30秒截止，缺失行动默认守护自己；恢复访问按原截止逐轮追算，最多16轮。连续两轮未确认给具体席位提示，不推断离线。
- UID独立成员指针、房间行锁、同一round允许双方确认；创建/加入/行动/撤退/取消都有内容指纹及请求回执，未知结果保留原请求ID重试。
- 单人撤退立即结束；双人二次确认后本轮结束离场，离场才释放新开资格；旧房间后续结算、旧创建/加入回执重放均不回写新指针。倒地仍留队者继续占本房资格。
- 约2秒加错峰短轮询，单页串行、隐藏停止、恢复立即同步、错误退避至15秒；前台操作未知时自动更新状态，也可以同一ID重试，刷新后仍能恢复未确认请求。
- 独立保存胜负、模式、规则版本、回合数、生还人数、用时和每局记录；最近十次结果用两个独立索引查询在PHP中合并/去重/同时间按ID排序。没有全服榜和积分。
- P1音效、飘字、守护/破绽与台词接到论坛页面；BGM独立默认关闭、低音量、交互后播放、隐藏/终局暂停，同页其他可听媒体播放时让出。
- CSS仅作用于`.gcr`，页面内不使用普通全局ID；玩家头像使用论坛现有avatar返回值，失败时保留席位占位。

已定数值、`raid_rules.php`、`P1-REFERENCE.json`和`balance_check.py`未修改。单人首领120/恢复3，双人130/各2，30秒/16轮保持不变。

## 4. 给小蓝的部署顺序

1. 在独立测试站备份插件完整代码、插件配置和数据库。对照候选包的SHA256清单，确认来源基线为上述P1提交；不要拿本包直接覆盖生产站。
2. 如在Git工作区，先切独立P2分支；应用包内`raid-p2.patch`前运行`git apply --check`。也可将包内`source/plugin/gamecenter/`作为完整插件候选。所有memory素材及原SDK均保留，不能只复制`games/raid/`。
3. 通过后台正常更新插件为候选1.3.0；`upgrade.php`复用安装入口建三表，扫描登记raid。升级新游戏默认未开放；检查三表均为InnoDB、同一物理库/连接。已有9表和记录不改变。
4. 确认raid奖励配置为0后，仅在测试站开放。更新缓存，打开`plugin.php?id=gamecenter&mod=play&game=raid`，使用两位真实测试会员。不要使用样稿双席位按钮代替联机。
5. 第5节通过后记录实际候选文件清单、环境和结果，交用户试玩。此包没有替你完成论坛部署或main合并。
6. 可选在既有Discuz调度中包含`cron/raid_cleanup.php`；它每次最多追算50房间，不建常驻进程，不删历史。未配置时访问房间同样有界追算，不承诺无人访问时准点写库。
