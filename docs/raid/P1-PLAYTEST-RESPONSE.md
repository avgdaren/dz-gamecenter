## 1. 等队友：首轮联机采用的策略

| 场景 | 决定 |
| --- | --- |
| 正常选择 | 保持每轮 25 秒逻辑截止，双方存活成员确认后立即结算；界面直说“最多等 25 秒”，不用猜是否还要等满倒计时 |
| 一方没确认 | 到期只补“守护自己”，既有确认仍执行；不攻击、不恢复，不替玩家自动通关 |
| 连续未确认 | 连续 **2 个已结算回合**使用默认动作时，标明具体席位与次数，提示可等待或由自己撤退；下一次确认后清除连续提醒 |
| 网络状态 | 只能证明“未确认”，不能根据没有动作宣称“已离线”；P2 即便有请求时间，也区分网络连通与是否操作 |
| 不愿继续等 | 保留单方撤退，不需要队友批准。双人本轮结束后离场，未确认则守护自己，已确认动作照常执行；最多等当前轮剩余时间。另一人可按原双人规则继续 |
| 退出后的数值 | 不自动转单人，不把首领降到 120、不补恢复，也不自动踢人／强制判负。避免故意断线换取难度优惠，继续使用 130 上限与 65 阶段阈值 |
| 思考时间 | 当前不加暂停、续时或按设备改变时限。25 秒保留为已定 P1/P2 首轮基线；若真实手机双人试玩明确不足，另改规则版本、时间预算与回归，不偷偷改当前 baseline |
| 轮询 | 约 2 秒轮询只决定何时看到结果，不能给迟到请求补时；结算时刻仍按原 deadline，下一轮截止也不后移 |
| 等待大厅 | P2 实现 5 分钟无人加入后取消。界面明确“邀请已过期，可重新建房”，不再显示可加入；成员资格释放、旧链接拒绝、刷新恢复与到期清理都需验收 |

P1 现在补“每轮最多等待”的常驻说明和连续未确认提醒，复用既有撤退；没有新增战斗行为或服务器状态字段。提示基于服务器 history.defaults，倒地、离场、终局和单人不会被误报为队友挂机。

这套方案让正常配合尽快结算，并给不想继续的一方明确退出方式。对方整局没操作时，在线者确实承担原双人难度；不把这种情况伪装成正常单人体验。真实联机首轮重点测每轮等待时长、连续超时频率和撤退是否清楚，再判断是否要另设可选的更长时限。

## 3. 音效与受击：现在在 P1 收尾交付

已经补到本机样稿，全部为表现层：

- Web Audio 实时合成攻击、受伤、守护、恢复、破绽、阶段转换、胜利、失败、截止提示；使用现有游戏同名的 `gcm_sound` 偏好键，可随时关闭。P1 本机样稿和论坛不同源时独立保存，P2 同源后可沿用，不能声称现在已跨源共享。页面初载不会自动请求发声，首次点击操作才解锁。
- 首领和玩家的伤害数字、恢复数字、守护生效标签、血条闪光、轻微受击位移，回气破绽有持续金色强调；每轮还有独立文字摘要。
- 治疗与受伤分开显示：先显示实际有效治疗，再显示实际受伤，不用净血量变化掩盖先治疗后受伤。溢出治疗不冒充有效治疗，过量伤害不冒充实际扣血。
- 不改服务器结算。以新 history 为依据，一轮最多一次；相同 GET、原 ID 重试、刷新基线不重播。后台恢复和一次跨多轮追算只给摘要，不连播历史音效／飘字。
- 静音立即停掉已排定的音符；页面隐藏停止声音与短暂视觉效果；音频节点在结束后断开并释放，最多 24 个声音节点组、每次结算最多 8 个视觉提示，短音本身不循环；第二轮新增BGM由独立开关和生命周期管理。
- 减少动态效果时保留文字、生命条和静态破绽提示，禁用飘字与位移。音效偏好独立于减少动态效果，可另关。

未调用外部 CDN、字体或图标库；第二轮BGM使用随仓库交付的本地文件。音效是否悦耳、手机是否允许解锁、飘字是否遮挡按钮，这些必须试听和真实浏览器操作判断；模拟 AudioContext 只验证调度、静音和资源释放。
