## 1. 单人难度：补证据，提出 P1 候选

原企划只验证了单人存在通关路线，缺少常见策略和局部失误实验；不能由此断言符合“高难但有策略空间”。独立复算确认原 2 次恢复数值下，回执定义的稳健策略第 14 轮死亡，首领剩 10。

P1 推荐候选为 **单人恢复 3 次、双人每人仍 2 次**，保留 130 首领生命、40 玩家生命、28 恢复量、16 轮和 25 秒期限。模型默认导出该候选，原规则保留为 BASELINE。

**用户尚未确认最终难度。** 本修订把候选和对照准备好，不把审阅建议写成用户已批准的终值；P1 可玩样稿、真人难度及正式实现均未交付或启动。

## 3. UNION 的兼容性核对

回执建议 SQL UNION 合并历史，但官方默认 querysafe 的 daction 含 `unionselect` 和 `unionall`。官方 DB 类的 checkquery 会拦截该查询，与先前 SELECT @@SESSION 问题属于同一层。

使用仓库外的官方 `discuz_database.php` 原字节文件（Git blob `f4b457fcc62692aa93eea1fa31ad5559265030ad`），通过 `discuz_database::checkquery()` 运行 **3 项检查通过**：

- `SELECT ... UNION SELECT ...` 被拒绝。
- slot0 历史独立查询通过。
- slot1 历史独立查询通过。

查询两分支各自前 10 条足以组成合并后的前 10 条。实现时在 PHP 合并，保持安全检查开启；不需要关闭 querysafe 或另建 SQL 白名单。P2 仍需真实数据库 EXPLAIN、去重/同时间排序及并发集成检查，此处没有执行 SQL 或连接数据库。

## 4. 复现与交接

仓库根目录：

```text
python3 docs/raid/balance_check.py
python3 docs/raid/balance_check.py --trace
```

`--trace` 输出仍执行完整核对；可将 JSON 重定向到仓库外临时文件，不提交测试账号/运行日志。

PHP 安全检查只需本机原版 Discuz 源码，不读取站点配置或凭据、不连接数据库。设置 GC_DZ_ROOT 为该源码根目录后运行：

```text
php docs/raid/querysafe_check.php
```

也可把源码根目录作为第一个参数。脚本输出实际文件的 Git blob 哈希，便于区分本机 Release；不同版本需按实际结果记录，不能凭此认定所有站点均验证通过。

本修订仍只有企划、规划脚本和文档索引；无生产插件变更、无数据库迁移、无部署、未合并 PR #9。后续先确定 P1 采用的数值候选，再进行纯 PHP 规则与可点击样稿，实机及美术仍按企划阶段推进。
