## 1. 当前定案

| 参数 | 单人挑战 | 双人合作 |
| --- | --- | --- |
| 首领初始/最大生命 | 120 | 130 |
| 玩家初始/最大生命 | 40 | 每人 40 |
| 恢复次数 | 3 | 每人 2 |
| 每次恢复量 | 28，封顶 40 | 相同 |
| 普通/破绽攻击 | 10 /20 | 相同 |
| 阶段阈值 | ≤60 | ≤65 |
| 回合上限/期限 | 16 /25 秒 | 相同 |

规则版本 `raid-v1-p1-balanced`。`Rules.solo_boss_hp` 用于单人，现有 `boss_hp` 保持双人 130；`initial()` 按原始人数取上限，阶段按固定模式上限计算。成员倒地/离场不会改变模式、首领上限或恢复预算。

设定写作“基础生命 120；双人获得月蚀加护 +10 生命”。只有总生命差异，不添加额外护盾层、减伤或破盾玩法；同一只首领共用一张图。

**数值不再待拍板，可以作为 P1 的固定输入；真人手感尚未验证。** “高 2–3 个点”作为用户体验目标，不将离线样本换算成统一的难度分数。当前提交仍只有企划、规划脚本和参考数据，游戏本体尚未开工，数据库未升级。

## 2. 数值复算与实验口径

| 检查 | 最初版 130/2 | 上一候选 130/3 | 已定 P1 120/3 |

| 单人合法通关序列 | 18 | 43 | 574 |

| 所有通关中最高剩余生命 | 10 | 24 | 30 |

| 双人掩护 | 6 轮胜，19/22，不用恢复 | 相同 | 相同 |

稳健策略定义保持不变：重击先守护，其他非回气轮生命 ≤20 且有次数则恢复，否则攻击；回气轮攻击。阈值 ≤24 的结果相同。

本轮留言的 2/32→9/32 使用 **稳健路线 `AAGAHAGAHAGAHAGA`**；之前 v0.2 的 1/32 使用 **原参考路线 `AAGAAHGAAGGAHAGA`**，不是同一个实验：

| 单点替换且后续脚本固定 | 上一候选 | 已定 P1 |
| --- | --- | --- |
| 稳健路线 | 2 胜 /17 败 /13 非法 | 9 胜 /10 败 /13 非法 |
| 原参考路线 | 1 胜 /30 败 /1 非法 | 14 胜 /17 败 /1 非法 |

双人掩护的 12 个攻击↔守护单点替换仍为 11 胜 /1 败。非法动作表示验证应拒绝，不能记作已经输掉一局；固定后续脚本不模拟玩家重新规划。这些限定实验支持比较规则，不代表真人胜率，也不证明只有一条解或精确相差几个难度档位。

当前模型 **45 项检查通过**，七组历史/变体（18 /43 /574 /635 /173 /22 /2959）保留在输出中。双人参数及 6 轮 19/22 的掩护节奏有独立断言；单/双人阶段和双人一人倒地后的阈值有断言。

## 3. P1 逐轮对照交接

已提交 [P1-REFERENCE.json](P1-REFERENCE.json)，包含规则、公共常量、动作码、六例初始状态及逐轮期望值：

- 单人保留原参考路线：16 轮胜，剩 10、余 1 次恢复。
- 单人较短路线：14 轮胜，剩 14、余 1 次恢复；不再沿用旧版的 15 轮/剩 4。
- 单人稳健路线：16 轮胜，剩 14、恢复用尽。
- 双人掩护、保守与援护：分别 6 /8 /8 轮胜，保持原双人结果。

PHP 规则需按相同 mode 和输入，逐轮比较预告的阶段/目标/伤害、行动、玩家生命、首领生命、剩余恢复和结算后破绽。不能只比终局；不能在有人倒地时将双人首领重算为单人参数。

生成是确定性的，没有账号、UID、本机路径或时间戳。规则变化时同步更新版本、脚本、JSON 和企划。

```text
python3 docs/raid/balance_check.py
python3 docs/raid/balance_check.py --trace
python3 docs/raid/balance_check.py --write-reference docs/raid/P1-REFERENCE.json
```

## 4. 已处理的工程意见

| 回执意见 | 当前规范 |
| --- | --- |
| 历史索引 | 两条独立 slot0/slot1 历史索引；各查终局最近 10 条，PHP 去重/排序取 10。 |
| member 释放 | 保留最近房指针；锁内追算后判断 WAITING/ACTIVE 且本人未正式离场才 active；终局/离场可新开；旧房清理和请求重放不覆盖新指针。 |
| 超时 | 保留守护自己；空过仍损失输出且失去减伤/破绽。P1 检查迟交后的实际体验，不承诺任意超时可补救。 |
| 容量 | 记录实际 php-cgi worker、PHP_FCGI_CHILDREN、环境/网络、同配置空载基线及 worker 内存；参考为四 worker，讨伐容量仍待实机测。 |
| JSON | state_json/result_json 均 TEXT NOT NULL，分别限制 16384 /4096 字节；摘要最多 16×512 字节，严格解析与 schema 检查。 |

历史查询采用两次 SQL，不使用 UNION。官方默认 querysafe 含 unionselect/unionall；此前官方类 `discuz_database::checkquery` 三项回归确认 UNION 被拒、独立查询放行。官方测试文件 blob 为 `f4b457fcc62692aa93eea1fa31ad5559265030ad`；小蓝的本机版本 hash 不同，但其独立三项检查也通过，见复核留言。没有将某个版本的结果外推为所有站点通过。

设置 GC_DZ_ROOT 为本机原版 Discuz 根目录后运行 `php docs/raid/querysafe_check.php`，或把根目录作为第一个参数。脚本不读取站点凭据、不连接数据库；真实查询/EXPLAIN 仍待 P2。

P1 下一步为纯 PHP 规则及可点击样稿；P2 真实联机、P3 插画、P4 绑定提交实机验收按企划执行。本修订不包含这些游戏实现，也没有直接修改 main 或合并 PR #9。
