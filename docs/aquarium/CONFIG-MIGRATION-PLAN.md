# 水族馆配置迁移与1.4.0接入决策

日期：2026-10-29；作者：GPT / Codex；原插件 (C) 2026 Carinoasd。

来源：PR #25 小蓝回执6494171580。本文件是上线前方案及执行要求，**不是已经实现/执行的迁移工具**。实际迁移工具和断点/恢复验证属于正式内容上线前的门槛，不能仅凭本文宣称已有档可升级。

## 1. 1.4.0基线与已有存档能力

小蓝报告本地站1.4.0已有通用save/load/delsave槽位接口，每账号每游戏3槽、单档64KB，save_put直接保存客户端JSON。仓库main仍为76d226d的1.3.0；所有现有分支头未发现1.4.0定义。当前没有完成重基线，禁止用PR #25的1.3.1候选覆盖本地1.4.0。

取得完整1.4.0源树及提交SHA后才做冲突合并，不能只把版本号改大，或按评论拼造save/chunk等入口。保留全部原op、游戏、表和槽位行为，新增aquarium增量；安装/升级必须根据实际源码确认。

## 2. 为什么不复用通用槽位存档

1.4.0有持久化能力；水族馆选择独立表不是因为平台没有存档，而是需要服务器验证、串行结算及版本一致性。

- 金币、图鉴、捕获计数、保底、随机种子/序号、结算锚点、购买拥有权必须服务端权威，不能信任save_put中的任意JSON。
- **活动布置也保存在同一水族馆存档。**鱼位需校验已发现鱼、唯一性和容量，装饰需校验购买拥有权/放置层，背景需校验有效ID；布局不能被过期页面用整档覆盖。
- 将布局拆进通用表会增加跨表/跨版本一致性、三个槽哪一个为活动布局、跨设备恢复等规则，而水族馆仍然需要自己的权威表，不会减少这张表。
- 展示偏好将来可单独保存，但首版不混用两种存档。若以后提供布局预设导入，仅把其作为不可信输入，经拥有权/容量/版本校验后写入水族馆；不从预设导入金币或解锁状态。
- 不改平台通用save/load/delsave契约，也不读取通用槽位作为水族馆权威档，保留其他游戏兼容性。现有A阶段尚未实现正式布局功能，上述为后续实现决策。

## 3. 配置迁移政策

**离线上限已由用户确定为24h，72h不再是待定项。** 本轮不改cap、价格、权重或冻结hash；因此不需要把现有测试档从24h改到72h。

严格匹配config_version/pool_hash/config_hash是防止拿新规则静默重算旧收益的保护。未来调价、改周期/概率/上限，均生成新config_version，不能只改常量并期待读旧档自动兼容。

### A. 上线前准备

- 将每个已用的配置、随机协议、规则读取器以版本归档；部署包同时包含被迁移的旧版本与目标版本，固定ID映射。
- 保留旧金币/图鉴/计数/随机序号，不因调价补扣款或回溯重抽。仅价格变化也走显式迁移，但过去生产仍按旧规则。
- 移除鱼种/水域、改变ID含义或缩减容量时必须有显式映射与冲突处理，不能丢弃已拥有资产。无法表示的档案列为失败，不直接写目标版本。
- 先在从备份恢复的隔离库执行dry-run，输出账号数量、版本分布、资源变动汇总与失败UID清单；不输出seed或用户私密内容。工具不得默认连接正式库。

### B. 维护窗口及每行事务

1. 暂停水族馆所有会落账请求，排空在途事务；其他游戏正常运行。备份水族馆表、旧代码/配置，先验证可恢复。
2. 选统一切点T，须不早于已有档的最大结算锚点；T和源/目标版本写入迁移任务记录，恢复执行不得另取一个T。
3. 对每个UID锁行。源版本不匹配则按策略跳过/报错；已经迁到目标版本的行只校验跳过，不能重结算。
4. 用旧配置settle(save,T,old_config)：沿用旧上限（当前24h）及旧周期/权重/价格；超过上限仍按原规则丢弃，锚点推进到T。
5. 按映射转换必要结构。周期变化时余数用floor(old_progress×new_period/old_period)；保留完成比例，不追溯加速。更新版本/hash，校验所有ID、余额、计数和布局。
6. 规则状态、结算摘要、row config_version/save_version、updated_ms=T及version+1同事务提交。只更新JSON版本而漏改row列会导致decode失败，禁止分两次保存。
7. 分批以UID游标记录进度，失败行保持旧数据；任务有明确重试/终止机制。用户请求继续保持维护态，不把旧版本人群提前开放。
8. 全量确认只剩目标版本、无失败/损坏档、总量与dry-run预期一致，抽样验证后开启目标配置；T之后的时间按新规则累计。

### C. 失败、恢复与回退

- 提交前失败：原档不变，可以按同一T安全重试。提交后丢响应：目标版本判断跳过，避免重复发奖。
- 混合版本期间不得开放仅认识新配置的服务；损坏档不回退重建，隔离并修复。
- 若尚未恢复玩家写入，可回退旧代码/配置及整张迁移前表备份；两者成对恢复，不能仅回退代码读取新档。
- 已开放且产生新版本进度后，不覆盖旧备份；先停写，采用另行验证的逆转换或前向修复，保留新增进度。

## 4. A阶段测试档与正式档

当前只有管理员占位测试，config为aquarium-foundation-v1，并非正式鱼种ID。正式上线前，先导出/保留测试档，选择验证过的转换或由管理员明确确认仅重建本人测试档；不默默清表，不将这一策略用于正式玩家。

在正式配置、迁移工具、dry-run/重复执行/中断恢复/备份恢复验证完成前，继续默认关闭，不把A阶段测试档声明为永久兼容正式内容。

## 5. 上线前必须有的迁移验收

覆盖：旧价格→新价格不补扣；旧周期结算与新余数；24h上限不重发；概率表变更保留catch_seq；新增/移除ID映射；row与JSON版本一致；重复执行；批次中断；提交前/后故障；备份恢复；混合版本不得开放。实际工具完成后需原版X5驱动与真实库验证。
