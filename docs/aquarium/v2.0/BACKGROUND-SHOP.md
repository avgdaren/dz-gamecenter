## 卡片与购买流程

1. 未拥有：点缩略图或“查看购买”打开预览。即使条件不足也允许看原图，在弹层列出缺金币/发现种数/水域条件，禁用购买按钮。
2. 条件满足：弹层显示背景名、永久拥有说明、本次花费和购买后余额；“确认购买”为唯一扣款动作。取消、Esc 或关闭都不扣币。
3. 购买成功：弹层转为“已拥有”，隐藏付款摘要，主按钮变“使用此背景”；不自动切换当前鱼缸。卡片与金币使用服务端返回值更新。
4. 已拥有：卡片“使用”或预览中的“使用此背景”发出一次只改背景的 layout 请求。切换免费，鱼、装饰和钓点不变。
5. 已在使用：显示“使用中”，不会再次保存或购买。所有购买/切换在 busy 或结果不确定期间禁用；失联先同步，再决定是否重试。

购买与使用是两步，不做两个请求拼接的“购买并使用”。不能先乐观扣款、换图，再期待服务端拒绝后回滚。

## 商品与解锁条件

旧四景沿用当前 catalog 的价格及全部条件；本轮没有重新定价。秘境沿小蓝交接的 10,000 金币与无额外条件。所有商品都是纯外观，不改变钓点、捕获概率或金币产出。

| 背景 ID | 名称 | 金币 | 条件 |
| --- | --- | ---: | --- |
| `tank_day` | 日光 | 0 | 初始拥有 |
| `tank_moon` | 月光 | 0 | 初始拥有 |
| `tank_sakura` | 樱溪浅梦 | 600 | 池塘发现至少 3 种 |
| `tank_coral` | 珊瑚晴湾 | 1,200 | 已解锁浅湾 |
| `tank_star_ruins` | 星眠遗庭 | 2,400 | 图鉴发现至少 6 种，且已解锁浅湾 |
| `tank_aurora` | 极光冰湖 | 3,600 | 图鉴发现至少 10 种，且已解锁浅湾 |
| `tank_firefly_grove` | 萤光秘境 | 10,000 | 只需金币 |

“发现”计算真实已发现的鱼种数，不是 catch_count，也不随售卖减少。条件只限制首次购买，已拥有后不会因任何计数变化失去使用资格。金币由服务端结算后检查。

## 统一拥有字段与旧档衔接

采用已有背景 catalog 声明的 **`background_owned`**，不另起 `bg_owned`，也不混进 `decor_owned`。增加独立标记 `background_schema: 1`，保持当前 `save_version: 1` 不变。

```json
{
  "background_schema": 1,
  "background_owned": {
    "tank_day": 0,
    "tank_moon": 0,
    "tank_firefly_grove": 1794146400000
  }
}
```

值为拥有时间的整数毫秒。两种免费背景用 0 标记初始赠送，购买项使用本次服务端时间。示例时间为演示值，不是玩家数据。

- 新建档直接带标记及两个免费项；background_owned 在 JSON 中始终为对象，不能有列表/数字/空字符串等别名形态。
- 两字段均不存在才是可迁移旧档：在原有锁/事务内补两个免费项与标记，保留其余字段；不要重建存档，不重算捕获，不额外领取 24 小时收益。
- 若两字段之一存在但另一字段缺失，标记未知、时间非法、拥有未知 ID，或当前背景不属于已拥有项，应按异常档隔离；不能通过默认值/强转把它“修成”合法档。
- 当前旧实现只允许两种免费背景。若遇到无拥有字段却正在使用付费背景的旧档，不据此白送该商品或静默改回日光，留只读错误并人工核对。
- 同一旧档迁移重跑为 no-op；由现有 store 统一管理行 version。迁移本身不改 coins、fish、rod_level、catch_seq、pool_hash、config_hash 或 last_settled_ms。正常请求如需结算，沿既有结算路径执行一次，不能因补字段再结算一次。
- 数据仍保存在现有 state_json，不需要 SQL 建表或加列；本交付未实施或验证实际迁移。

## 服务端接口与校验

沿用 `op=aquarium` 和现有鉴权、formhash、锁、事务与 expected_version；不改 api.start、api.submit、game.json 或后台参数结构。

### 购买

新增 action **`buybg`**，与装饰的 buy 分开。请求只接受 `background_id`、`expected_version` 和 `catalog_version`；catalog_version 是服务端返回的背景目录版本/摘要，用于拒绝过期报价。不接受客户端传入价格、拥有列表、背景路径、时间或金币增量。

1. 锁内核对版本，按原有流程结算一次并验证存档。
2. 取服务端冻结的背景目录；核对 catalog_version、ID、价格整数范围、购买条件与金币。
3. 已拥有的 ID 不再次扣款或重复发购买回执；使用已有状态返回。重复请求版本冲突时返回最新快照，前端确认已拥有后结束，不拿旧报价盲重试。
4. 同一原子写入完成扣币、background_owned 时间及有界购买回执。失败整笔不落库，不出现扣币无物品；与现有版本/幂等机制一致。
5. 禁售开关只关闭新购买，不删拥有记录，不令当前付费背景非法。

### 使用与目录

使用现有 action **`layout`**，只传 `layout: {"background":"目标ID"}` 及 expected_version。现有 setLayout 支持局部背景更新，直接复用；不要求前端重传可能已过期的鱼和装饰数组。

- `backgrounds()` 或等价目录返回 7 个合法 ID；它仅说明“商品存在”。`validateState()` 与 `setLayout()` 还必须检查“账号已拥有”，不能只扩白名单。
- 购买、目录、迁移、存档验证和 renderer 使用同一份受信配置。鱼池指纹不因 UI 或背景商品变化而重算；背景目录单独版本化，价格文件不能随意热改。
- 保持已有 `rules.backgrounds` / `catalog.backgrounds` 数组类型不变；新增 `catalog.background_shop = {version, items}` 承载商品对象，避免把原 ID 数组替换成对象列表。
- items 至少含 id/name/description/cost/main/mobile/thumbnail、owned、active、missing；missing 沿用装饰结构 `{coins, pond_fish, total_fish, water}`，服务端计算。前端不根据 catalog.js 演示数据决定正式价格。
- `requires.pond_discovered / total_discovered / water_unlocked` 由目录加载层明确映射到购买校验；不要原样传给只认识 pond_count/total_fish 的装饰函数。
- 刷新、版本冲突及丢响应后，以服务端快照为准；不能把本地预览态当作已使用或已购买。
- 背景路径只从静态目录按 ID 取，相对路径需限制在插件 assets 中；不要拼接用户提供路径。

## 四组预设如何衔接

沿用先前免费预设规则：预设本身不售卖，不自动购买或发放背景/装饰。

- 目标背景已拥有：套用已拥有的成员与目标背景，保留全部鱼；缺少装饰按既有规则跳过并列明名称。
- 缺目标背景、仍有可用装饰：先提示“缺少萤光秘境背景”，提供“查看背景”和“保留当前背景应用”。只有用户选择后才提交有效 layout，不偷偷把未知/未拥有背景传给服务端。
- “查看背景”进入同一个商品预览/购买流程；退出后重新读拥有状态，再显示预设提示，不自动接着套用或扣款。
- 全部装饰都缺失：保持当前全部布景，即使背景已拥有也不借预设切换；提示缺件。缺主景时继续提示简化布景。

因此四组预设不用整体标成不可用，也不能把“免费预设”变成强制先买背景才能用已购装饰。若本轮只发布 UI 稿而后台未接，仍保留当前背景并提示，不能把新背景临时加入白名单绕过拥有校验。

## 美术与移动端边界

旧四景的主图均为 1536×960、手机图 768×480、缩略图 320×200，12 个文件齐备且可解码。秘境为 1536×960 / 768×480 / 240×150；同为 16:10，原缩略图比例正确但像素较小。

本轮从主图机械导出三个 320×200 缩略图：日光、月光、秘境。日光/月光源主图为 1600×900，按当前 cover 展示方式居中裁成 16:10；秘境由 1536×960 原主图等比缩小，不放大原 240×150 缩略图。原母图和旧缩略图均保留。旧四景直接复用现成缩略图，共七张卡片统一为 320×200。

正式接入复用当前 picture/mobile 路径与美术映射；新背景切换时还要更新原有的布景调色和音乐场景选择，缺少特定规则时回退现有默认，不增加捕获属性。大图预览只展示实际背景，不额外画一个与游戏不符的包装场景。

交互稿带 viewport meta；真实论坛模板是否下发 viewport 未验证。本仓库禁止修改 Discuz 核心/模板，因此不能为了手机测试擅自改模板。先在真实模板读取 viewport 和实际渲染宽度；如需适配，由插件已授权的容器/入口处理，并另验真实手机。浏览器视口模拟通过不能等同于真实手机验收。

## 回滚口径

**不能直接恢复只认识两个背景的旧程序。** 当前 defaults() 会把未知背景改回日光，validateState()/setLayout() 会拒绝付费背景；旧 1.x 还可能不认识 v3 鱼池和 Lv.5。不能承诺 raw rollback 无损。

为本功能准备“兼容关闭版”：保留最新鱼池/存档解析、background_schema/owned、七景校验及资源映射，只关闭 buybg 和商品购买入口。已有付费背景仍可显示，拥有记录、金币、交易回执与当前 layout 不变，免费使用已拥有背景继续有效。

发布前留一份完整备份；正常回退使用上述兼容代码，不回退真实交易数据。如果必须恢复旧数据库快照，需单独处理快照后的所有交易，不把这类操作包装为普通代码回滚。本轮没有创建、运行或验证兼容关闭版。

## 必须完成的接入验收

| 范围 | 需要看到的结果 |
| --- | --- |
| 基本购买 | 合法条件与余额下，准确扣一次币、得到拥有记录；当前背景不自动变 |
| 条件与非法输入 | 未解锁、金币不足、未知 ID、伪造价格、旧目录版本、错误拥有字段均被拒；余额和原档不半改 |
| 布景使用 | 仅已拥有可切，免费，重开后保留；鱼/装饰/钓点不变，原七景资源映射可读 |
| 并发 | 同 expected_version 同时购买只有一次成交，无死锁；买与切换相撞时快照能恢复一致 |
| 迁移 | 原两景旧档正常补字段；重复迁移不结算收益；异常混合字段隔离；已有新鱼/竿/出售记录不受损 |
| 预设 | 四组新预设在有背景、缺背景、缺主景、全部缺装饰四类状态下都符合上述规则 |
| 回滚 | 购买后的档进入兼容关闭版可读可用；不丢币、拥有记录或历史回执，不重置付费背景 |
| 界面 | 320/360/390/768/桌面宽度不溢出；确认/取消/已拥有/使用中/不足金币/条件未达/失联态正确；真实论坛与手机另验 |
