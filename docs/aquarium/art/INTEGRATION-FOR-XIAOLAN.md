## 1. 取用资源

以PR #34的193715af583d73897098bbd3af0be6d46c1e5f4a为内容基准，加PR #37资源增量。不要拿旧main的1.3.0覆盖现站。插件仍1.4.0，游戏前端版本和manifest缓存版本可按实现实际修改。

运行清单在 `source/plugin/gamecenter/games/aquarium/assets/manifest.json`。读取显式items，按kind+id查主图/缩略图，加入固定资源根目录；不接受客户端传路径、不按扫描顺序决定鱼种。每个files项有role/main/thumb/mobile、尺寸、字节和hash。

- fish/decor主图与128缩略图都已提供；购买/图鉴按catalog的index排，而抽签仍按ASCII fish_id，不能混用。
- 鱼主图朝右，可水平翻转游动，不要给建筑/文字类物件盲目翻转。所有标识文字由UI绘制，不在主图里。
- 装饰anchor=(0.5,0.9)，鱼=(0.5,0.5)，以画布比例定位；示例CSS变换为translate(-50%,-90%) / translate(-50%,-50%)。content_bounds用于编辑框/命中范围，避免大块透明留白难点击。
- 背景桌面与手机版分别提供；只对背景进行铺满裁切，鱼和装饰按布局锚点重排，不能把整个鱼缸当一张图裁掉两侧物件。
- 背景tank_day/tank_moon与钓点pond/bay是独立概念；玩家选择浅湾捕鱼不强制换背景。
- 原PNG是制作母版，不在玩家页加载。按可见缩略图/当前摆放物件懒加载，页面隐藏暂停动画，减少动态有静态模式。不要一次解码41张母版。
- 缓存用manifest.version或单文件sha256参数；改资源后不要让旧文件无限命中。不要把美术manifest版本当config_version。

[资源包/总览](ASSET-PACK-v0.1.md)及[已认可概念](reference/approved-acg-concept.png)供具体UI设计。当前图片文件已齐，不等于已完成玩家界面或移动端性能。

## 2. 先处理配置与存档过渡

现行HTTP仍是foundation-v1，不直接换成content-candidate。按CONTENT-HANDOFF与CONFIG-MIGRATION-PLAN实现维护/备份/dry-run/显式ID映射；旧规则结算到统一切点，保留余额、种子、序号、发现时间和计数，row/JSON版本同事务更新，可重复/中断恢复。管理员测试档处理要明确保留或转换，不自动删。

本包无新SQL、无额外数据表。正式内容与已有单表兼容策略仍由小蓝实现并验证，不能用CREATE IF NOT EXISTS当迁移工具。

## 3. 实际购买、布置和玩家页

经济与活动布置同权威档，服务端按价格/条件/拥有权/容量/层/唯一性验证，expected_version+锁行事务保证并发只生效一次。丢响应先读档确认，不自动换version重购；已拥有不再扣款。鱼只放已发现种类，装饰只放已拥有，移走不丢资格。

图鉴/水域/装饰入口和具体UI由小蓝处理：已发现/剪影、首次时间/次数、类别/主题/拥有状态筛选、预览与购买差额；条件不足置灰并明说差多少。游客/无权限/断线/冲突/维护/空库/全部集齐状态要齐。正常观看隐藏编辑框，编辑态才显位置。

装饰位仍做6/8/10对照后定，不预先写死6。买齐24件不等于同时摆24件。优先保留中间泳道，建筑后层、摆件小面积点缀；具体遮挡要在真实UI里看。大厅显示和普通用户开放必须跟完整上线阶段一致。
