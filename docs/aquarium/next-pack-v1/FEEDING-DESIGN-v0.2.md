# 喂养系统方案 v0.2

作者：GPT / Codex；原插件 (C) 2026 Carinoasd。2026-10-30。Refs #49 / #32 / PR #33。
状态：预研，不是已实现功能。延续 v0.1 的免费投喂与无惩罚定位，更新为支持同种重复及16种生物候选；奖励扩展单独评审。

## 目标与可见体验

玩家回来收获后，能用约10秒和鱼互动，看到不同物种的回应。普通饲料免费、无限、无库存、无领粮操作；没有饥饿、死亡、脏水、减产、维护费、亲密度衰减或连续签到。离线24h、鱼竿速度、捕获概率/保底不受喂养改变。

入口是鱼缸旁一个“喂一喂”。点击后进入选点态；默认点在中部水面，移动端提供“在这里撒粮”而不是要求精确点鱼。点击有效区域撒6粒以内的食物，最近的最多4条展示实例缓缓靠近，其他鱼保持游动；吃完自然散开，总时长候选8～12秒。全局一次只存在一场投喂，重复点击不创建新粒子/循环；结束后仍可继续免费观赏。

无鱼时提示“先放入一条鱼”，不扣任何资源。点背景/装饰不能误触喂食；进入选点态才捕获水面操作，退出还原原交互。点击鱼原有收起操作与喂食态必须有明确优先级，不能一喂就把鱼收回。

## 不同轮廓的回应

| 类型 | 正常游动 | 喂养反应 |
|---|---|---|
| 原有圆身/长鳍鱼 | 复用各自游动实例 | 按距离靠近，错开抵达时间 |
| 月汐人鱼 | 横向滑行，长发/尾部以后单独制作动态 | 稍慢靠近，停留/轻摆；人脸不做整张波浪扭曲 |
| 铃伞水母 | 保持伞盖朝上，缓慢上下漂浮 | 向食物下方轻移，伞盖脉冲候选；不倒着冲刺 |
| 卷尾海马 | 直立悬停，短距离巡游 | 直立靠近和停留，不旋转成横躺小鱼 |
| 软糖章鱼 | 低层缓滑，腕足轻收放候选 | 沿低层靠近食物，不穿地板 |

每条展示实例按slot管理。重复同种共享图片缓存，各自目标/相位独立；熟悉度若未来做则按账号+fish_id合并，不能摆12条同种刷12倍。先不做永久熟悉度、饲料商品或成长条，避免把观赏变成新的必做日课。

## 分期

A：只做观赏投喂，后台金币请求为0。先让动作有趣、手机不挤，再评估下一阶段。切后台/减少动态时停止粒子与追逐，恢复后直接回正常泳态，不补演出。
B：如果选用操作奖励方案，在A入口复用一场有效互动，由服务端发一次回应奖励；另见 ACTIVE-INCOME-DESIGN-v0.1.md。关闭奖励开关后A仍完整可用。
C：熟悉度/新饲料/成长以后另议，不把未定义的进度字段提前放入存档。

相较v0.1，“喂养绝不关联收益”仅在A阶段成立；B是本轮用户提出操作增收后的新候选，尚未逐项批准，不伪装成旧决策已确认。

## 状态与验收

- 正常/无鱼/切景/收鱼/连点/后台/减少动态/断线均有清晰状态。切场景/收掉响应鱼时取消相应表现，释放临时目标，不重建整缸。
- A断网可以继续本地观赏；不显示虚构金币。B未确认发奖前只显示动画反馈，不能先加余额再假定成功。
- 12条鱼（含重复）同时可见，仅4条响应；食物不跨层盖住前景UI，不把所有鱼堆到同一坐标。纹理一次绘制完整角色，不复制半条鱼当尾巴。
- 360px手机能完成选点/取消；桌面和触屏一致。候选性能预算同原播放器，实际设备测定后再冻结粒子/并发上限。
- A验收须证明金币、捕获序列、last_settled_ms、保底完全不变；B另验鉴权、限额、丢响应与两标签。
- 指标观察自愿使用、重复观赏与负担感；不把点击次数当留存，不编造提升比例。没有实测数据前不承诺上线日期。
