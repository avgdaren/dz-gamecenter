# 天使水族馆：喂养互动策划案 v0.1

作者：GPT / Codex；原插件 (C) 2026 Carinoasd。日期：2026-10-29（北京时间）。Refs #22 / #32。

状态：用户同意先形成策划案；**未实现、未排期、不进入当前C内容施工**。本案的具体次数/时长/熟悉度曲线均为建议，不视为用户逐项批准。继续优先完成正式鱼种、图鉴、装饰与布置。

## 1. 目标与边界

希望玩家回来收取收获、调整布置之后，愿意多停留片刻看鱼，逐渐记住不同鱼的反应。喂养提供可见回应和陪伴感，不承担补齐图鉴/购买建筑所必需的生产任务。

保持现有定位：不喂不死亡、不减产、不掉熟悉度，无饥饿警报、连续签到、定点喂食、疾病或照料费用。24h补算、捕获概率/保底/鱼竿效率不因喂养改变。没有论坛积分、付费道具或繁殖功能。

## 2. 第一轮试验：撒粮→聚拢→吃食→散开

1. 鱼缸中放一个“喂鱼”入口。点击进入撒粮态，再点水面/鱼缸有效区域确定位置；手机也有默认投喂点，不能仅靠精确点按。
2. 撒下少量可见颗粒，已展示鱼向附近聚拢；没有展示鱼时提示“先放入一条鱼”，不消耗任何东西。
3. 各鱼保留性格差异：晴蓝鱼先靠近，羽鳍鱼慢慢绕近，星斑鳐贴近底层等；这些是动画表现建议，不新增饱食度或伤害规则。
4. 吃食结束后平缓回到原泳道。示例总时长约8～12秒，最终须手机与动画试验后确定。
5. 撒粮中按钮显示“鱼儿正在吃”；结束后可以再次观赏。频繁点击不叠加粒子/寻路任务，不发金币或可刷取奖励。

第一轮普通饲料免费、无库存、无领粮步骤，不设置每天必须喂一次的任务。离线不需要自动投喂，也不在后台补演出。

## 3. 后续候选：熟悉度

只有第一轮互动被认为有趣后再加入，不与第一轮捆绑开发。

- 熟悉度按fish_id归账号权威档，表示该种鱼与你的熟悉程度；同种鱼首版只展示一条，移出/换水景不清零。
- 可解锁主动游近、不同吃相、短暂围游等观赏变化；不解锁新的捕获鱼种，不提高金币/稀有率。
- 不喂不下降，不设置连续天数和断签清零；已经解锁的动作永久保留。
- 不用按点击数无限增长。有效互动窗口/收益上限/重复请求去重必须另做小规模试验后确定，不能把本案中的空位当最终数值。
- 在没有明确曲线前，不加进度条制造“每天需要刷满”的任务感，也不显示虚构的“还差一次”提示。

特色饲料留作更后期选项，可以改变颗粒造型或临时观赏表现；是否使用游戏金币、具体价格和频次另评估，不能挤占当前低价布置的节奏。

## 4. 体验状态

| 状态 | 表现 |
|---|---|
| 游客/演示 | 只播放清楚标注的演示，不创建账号喂养状态 |
| 只有纯动画试验 | 明示无收益；不发送经济写请求，不伪造服务器奖励 |
| 已有鱼、正常前台 | 允许撒粮，按钮和动画状态同步 |
| 无展示鱼 | 给出放鱼入口；不会扣资源 |
| 切后台/减少动态 | 停止粒子与聚拢动画；恢复后直接回正常泳态，不补播积压 |
| 网络中断 | 纯动画可退回静态观赏；将来若有熟悉度则不声称进度已保存 |
| 响应不明（未来熟悉度） | 只读同步确认结果，不自动重复记熟悉度 |

不让通知、红点或饥饿表情催促回访；恢复页面不能出现鱼“因离线不开心”。

## 5. 技术分阶段

第一轮仅本地观赏动画，不写生产档、不新增表。基于已有鱼位和前后泳层作短暂目标点偏移，不需要完整寻路或碰撞系统。粒子数/同时响应鱼数有限，结束后复用原动画对象。减少动态时用轻微靠近/静态反馈代替追逐。

若未来做熟悉度，必须先更新save_version/config_version及迁移方案，在既有水族馆权威档中保存进度；服务端校验账号、已发现/展示鱼、版本、有效互动条件，并在事务内处理。客户端不能提交熟悉度绝对值。纯动画反馈可以即时播放，但服务器确认前不显示永久解锁。具体去重协议须届时设计，不能直接套用当前捕获结算锚点。

## 6. 如何判断值得继续

先在已有图鉴与布置可玩的版本上试验，避免把内容扩充本身的效果归给喂养。

- 观察自愿喂养比例、重复观赏与回来看鱼的意愿，分别记录首次新鲜感和后续行为。
- 看少量用户是否能记住鱼的差异、是否感觉更有生命力、是否产生“又多一个每天要做的事”的负担。
- 点击量不等于留存；若采用事件统计，喂养启动/结束与回访应分开，采用匿名汇总，不在仓库记录用户行为数据。
- 试验前预先约定对照方式、观察窗口与停止条件；当前样本/流量未知，不编造百分比目标或保证提升。
- 若只有第一次有趣或让手机掉帧，保留为偶尔观赏动作或停止扩展；不靠加收益强迫使用。
