# Issue #65：金币自动刷新与装饰排布修复

作者：GPT / Codex（小典）；原插件 (C) 2026 Carinoasd。2026-11-04。

关联 [Issue #65](https://github.com/avgdaren/dz-gamecenter/issues/65)，依赖交接修复 PR #61。基于 `74fab2426f38b068aa91c8a95be121ea43d812b2`，独立分支 `codex/issue-65-aquarium-display-fixes`。下一版设计 PR #64 不在本补丁内；远端 1.2.1 的新音效仍需在发布集成时核对保留。

## 已修行为

1. 捕获到期后主动同步，以服务端快照更新金币。同步前不估算或虚增金币；逾期时显示 00:00，收到结算后才开始下一轮。初次取得存档目录后立即同步离线收益。
2. 定时器迟到、跨过一个或多个周期仍能触发同步；忙碌时不并发发送，失败至少间隔 4 秒再重试，隐藏及 pagehide 时不由倒计时发请求。原 45 秒兜底同步保留。
3. 相同结算时间/进度的只读 catalog 快照不再重置本地计时起点；较低版本响应不覆盖当前快照。金币增加时同时刷新装饰购买金额与按钮，避免金额已够但旧目录短缺值仍锁住按钮。
4. 装饰以同层数组顺序从左到右排列。按素材的**可见 bbox**留间距，宽件满层时统一等比缩小适配；保留各自落地点、原锚点、远近与氛围参数。前后景仍是独立层，允许正常景深遮挡。
5. 装饰卡片显示前景/后景与左侧/中间/右侧。已摆放的卡片增加左移/右移按钮，交换同层顺序；最左/最右边界按钮禁用，按钮不会触发卡片收起。存档继续使用原 `layout.decor.back/front` 字符串数组，刷新后位置顺序保留。
6. 布景预设的提示先转为数组左右顺序保存，避免刷新后依赖已经丢失的内存坐标；非法素材几何跳过渲染，不拖垮其余装饰。更新玩法说明，并修正“鱼竿会提高单鱼金币”的旧误述。

没有新增任意拖动坐标、存档字段、数据库列或购买规则。旧档合法摆件仍可用，但旧数组现在明确表示左右顺序，首次应用补丁时构图可能重新排列；满层宽件也可能变小。这是本次避免叠放的显示变更。没有自动部署或修改玩家数据。

## 根因与核对

- 原 `tickCountdown` 在剩余 ≤900ms 时请求同步，服务端当时尚未到期。下一次 tick 跨过周期后，取余会把剩余时间重置为下一周期，可能漏过这次到期结算，等待兜底同步或其他操作。旧基线已被相同测试复现为“到期前 100ms 就发请求”，新用例通过。
- 原装饰逻辑只比较少量 `preferred_x`，并用带透明留白的 sprite 宽度估计距离。三件争用两组推荐坐标时，没有连续空间排布与用户调整机制。两件弯月/星晶单独摆放不必然重叠，加入其他摆件或预设后可发生挤占。
- 排查时本地部署 game.js 与小蓝原工作目录哈希一致，为 `e1ede1b69ad4eca37ffc32857f47ae95ce77c19612e9e14edeecfd1727696857`；独立交接分支有此前修复，哈希不同。两边均保留上述倒计时与装饰选点逻辑。未修改小蓝工作目录或部署。
