## 先确认单粒投喂的两个数

- **一点1粒、场上最多8粒：采用。** 达8粒不删已有食物、不创建新节点、不响入水声，短提示即可；8粒是页面表现上限，不是饲料库存/付费额度。
- **沉底即消失：按用户最新确认采用。** 以9f3156b为准，饲料46 CSS px/s下沉，达到可视缸底时250ms左右淡出删除，解除认领和追逐，不播放咬合声、不扣任何资源。之前25秒计时过期建议撤回，不叠加独立计时玩法。粒子状态分开记录eaten与sunk，不让沉底的consumed误触吃食音。
- **显示尺寸采用桌面9px、手机7px**，继续使用32px透明源图，不缩回旧5/4px。
- 不存在持久“吃饱/饿”的状态。一条鱼只认领一粒、一粒只归一条鱼；当前同时接近/吃食最多4条，其他粒子可等待空闲鱼。每粒独立ID与generation，不再每点一下取消其他有效食物。
- 目标失效/鱼被收起后，尚未沉底的食物可重新分配；选择空间可达者，不能只用<0.9缸宽的距离就判慢速海马可达。按下沉轨迹预测，在沉底前不能赶到或无法避免拥挤时不认领。
- 最后一粒被吃掉或沉底后，安静4秒清场；其间新投放打断清场计时。后台/离开/切景/缩放时取消整场并清理，回来不补演出。长时间连点也不存在无人认领食物永久占满。

## 1. 四种新生物运动：参数已经可直接取用

上一轮评论6557593507已给数值，本次固化成 **motion-profiles.json**，以该文件为唯一数值源。它是前端表现配置，不进入捕获概率/存档hash。880px缸宽为参考，速度/摆幅乘W/880；不是每种都赋同一个cruiseF。

| 生物 | 巡航路径速度 px/s | 追食上限 | 总垂直速度上限 | 悬停上下摆幅/周期 | 翻转/停食姿态 |
|---|---:|---:|---:|---|---|
| 月汐人鱼 | 20–32 | 40 | 14 | ±3–5px / 3–4秒 | 仅左右转向，倾斜≤4°；脸稳定，轻探2–3px |
| 铃伞水母 | 8–14 | 20 | 22 | ±5–8px / 3–5秒 | 不翻转、不旋转；伞盖朝上，靠近后轻悬停 |
| 卷尾海马 | 10–18 | 26 | 12 | ±3–5px / 3–4秒 | 仅左右朝向，倾斜≤3°；直立停留，轻探1–2px |
| 软糖章鱼 | 14–24 | 32 | 8 | ±2–3px / 3–4秒 | 低层左右缓滑，倾斜≤3°；轻探1–2px，不腾空冲刺 |

垂直上限包含路径运动和局部浮动，四种都不允许为追食临时开启垂直冲刺。水母垂直浮游是正常运动，不是上下翻面。保持原PR #50 size_axis和批准的体型尺度，不能所有方图统一同宽。

浮动用独立相位的sin(2πt/T)，相对当前位置/路径锚点，不把sin逐帧累加到ny产生漂移；采样区间在生成实例/换目标时取一次，不能每帧乱变。水母/海马直立，章鱼中心偏下；范围细节见JSON，最终需按可见鱼体半高收紧边界。不同slot相位独立。

左右翻转需要方向连续稳定约350ms才切换，距离食物很近时不抖动翻面；转身缓动约600–1000ms，嘴/前缘朝食物，而非鱼中心压上去。到位后200–350ms停顿，再吃粒子；轻探放在独立内层，不覆盖外层巡游变换。静态图即可，不扭人脸、不复制鱼尾、不伪装有张嘴序列。

避让与独立停留位继续适用，尤其每次点1粒后不能让多条鱼抢同一粒。任何时刻只画一份完整角色。12条混合/同种重复、边角、360px必须实景验证。

## 2. 音效 v2：实际交付，不再用旧的软吃食声

路径 `assets/feeding/v2/`，另见 `docs/aquarium/feeding-audio-v2/README.md` 与可试听preview.html。

- **bite_01..04**：4个原创卡通短脆咬合变体，72/82/97/117ms，母版峰值统一**-8dBFS**；短噪声咬合+紧阻尼小冲击，无金属长尾。
- **drop_01..02**：107/132ms，母版峰值-10dBFS；每次成功创建1粒时响一次，满8粒拒绝时不响。
- **pop_01**：147ms、-12dBFS，已交付但**默认不启用**。若启用，仅自然完成且至少吃过一粒、最后一粒消失安静4秒后轻响一次；取消/后台/纯沉底不响。防止被误解成领奖。
- 4个bite足够，无需8个。默认无立即重复轮换，不强制随机音高。可选Web Audio playbackRate 0.92–1.08；HTMLAudio的preservesPitch可能使变速不变调，无法可靠关闭时只用四变体，不为此阻塞发布。
- 起始volume：bite .45 / drop .32 / pop .22。保持《气泡小步舞》及其现有音乐音量；**不能用瞬态峰值直接推算与BGM的主观响度差**，不承诺固定“高几dB”必然合适。先按上述值实机混听，再只调音效总线。
- bite消费确认后才触发，仍140ms全场间隔；drop独立100ms节流；所有投喂声音共享最多2声并发，bite优先，drop/pop忙时跳过。声音不排队，视觉消费照常；快速点击绝不能机枪式补播。
- 复用音效开关与交互解锁；场次取消释放引用。7个文件均给OGG/MP3、PCM WAV母版、时长/峰值/RMS/削波数和SHA。编码解码已测，无削波；实际听感及与BGM混音待用户/小蓝确认。

## 4. 旧→新迁移：按一次旧池结果精确对账，没有概率允许误差

适用前提：库存已合法迁移；已确定真实源版本、源配置/哈希与目标版本。来源未知/坏档只读隔离，不猜成新号。**库存补字段迁移**仍不settle、不改钱/锚点；以下仅指鱼池版本转换。

锁内读源档S，固定一个服务端N。记L=S.last_settled_ms、p=S.progress_ms、d=源配置该鱼竿周期、H=86400000。

```
T = min(max(0, N-L), H)
K = floor((p+T)/d)
p_after = (p+T) mod d
expected = 源配置/源规则对原始S单独settle到N所得结果
迁移结果 = expected + 目标配置标识/哈希（不额外结算）
```

相同seed、uid、catch_seq、源权重/保底决定同一捕获序列。允许金币差额**只能等于expected捕获列表金币的精确和**，不是[0,某个平均数]区间；普通期望2.64/5.06不用于单账号验收。任何金额/整数超限整体拒绝并保留原行，不截断、不先提交一半。

| 离线时长 | 有效旧池时间 | 精确对账 |
|---|---:|---|
| N=L（0） | 0 | K=0、金币/库存/序列/余数不变；仅切配置，行版本+1 |
| N-L=24h | H | K=floor((p+H)/d)，金币/鱼列表逐条对源oracle，余数按公式 |
| N-L>24h（含48h） | H | 与从同一个S结算到L+24h的捕获序列、金额、库存、余数相同；锚点跳到真实N，超额丢弃，不留作以后补领 |
| 周期边界 | d-p前1ms / 恰好 / 后1ms | 分别核对0/1/1条和余数，不因配置切换多出一条 |
| N<L（时钟回退） | 不切换 | 拒绝本次转换并保留原行/原锚点，待服务端时钟恢复，不用客户端时间绕过 |

逐字段核对：
- 和expected完全相等：coins、catch_seq、progress_ms、last_settled_ms；每种discovered_at/catch_count/owned_count/sold_count；no_new_count。捕获日志的顺序、fish_id、coins、is_new、caught_ms也对照。
- 和原S相等：uid、seed_hex、rod_level、current_water、unlocked_waters、布局、装饰/水景拥有、容量、已售回执、所有无关扩展字段。源结算若合法新增summary，只接受对应那一次捕获的摘要，不能改成“又一次奖励”。
- 仅转换修改：JSON config_version/pool_hash/config_hash与行头config_version、row.version+1。row.updated_ms=结果last_settled_ms，行头/JSON同事务提交。save_version不因多4种自动改号。
- 新4种在N前的旧池结算中不得出现；原12种发现记录不重建。库存守恒owned+sold=catch保持；迁移不新送引导鱼。

**分段一致性必须限定比较条件：**
- 同一源规则、同一初始状态、固定鱼竿/水域、总有效时间≤24h，单次旧池settle到N与按相同终点分段旧池settle的业务字段应一致。摘要是“最近一次”时内容可能不同，不能要求整份JSON字节一致；捕获日志拼接再比较。
- 超24h时，单次48h最多发24h，但两次24h合法访问可能各发24h，**不要求两者金币相等**。验证“旧池只消耗一次共享H预算、其余丢弃、切新配置不重开24h”。测试人为分块时必须传递同一个有效预算，而非每块各拿H。
- 两条对照路径的**旧→新切换点必须同为N**。把一条路径提前切新池再分段，捕获结果本就可能不同，不能拿它判迁移不一致。

**幂等与并发：**
- 同一个N重跑可用，但必须从第一次已提交的新档继续调用。已是目标版本时直接no-op，原始JSON与row.version/updated_ms不变，不新增结算/鱼/金币；不能把原S重新拷回库后再跑，后者只是可重复实验，不是持久化幂等。
- 用最新版本发正常sync且时间推进后允许正常新池结算，不把合法新收入判成重迁移。原expected_version重放得到conflict或明确的已完成读取，不换版本自动重放原售卖/购买操作。
- 两标签并发同一源行只转一次，来源验证/结算/写目标版本必须同一事务；故障回滚无半迁移，commit结果不明停任务并读原始行核实，不能猜失败后清库存。

需要保存私有逐行原始前后对账，GitHub只回聚合/合成夹具。源oracle是源SHA/源配置运行结果，不能用同一段新迁移代码自我证明。上述为验收合同，当前环境未运行PHP迁移。

## 5. 兼容关闭版：正常档继续可玩，异常档隔离，维护是另一种兜底

**主回退目标=可继续运营的16种兼容关闭版，不只是只读展示。** 必须包含最终新配置/哈希解析、4种终身上限、鱼竿门槛、A/M/80保底、完整库存；正常sync/捕获继续守恒，放入/收起仍按真实owned和12展示位。

- 售卖服务端硬关闭（文件误设all也拒绝，capability=false），保留已成交金币、库存、sold与全部回执，不逆转真实交易。
- 冷旧档也有合法版本路由与一次原子切换；不能只测试已切新版的热账号。旧/新冻结配置只读支持仍在，未定义来源/异常schema账号只读隔离。
- 喂养纯前端、人数纯聚合，两项可关闭而不影响存档与捕获；关闭喂养要移除粒子/声音/回调。B阶段发币不启用。
- 回退后新鱼仍可展示/保留/按门槛限量捕获，不能退回仅12种的旧目录/旧校验器；已收满3条不能因回退多钓。不改ACTIVE_CONFIG指回旧池、不删新鱼、不降哈希以绕过校验。

**若没有上述兼容包，紧急兜底=整个水族馆维护、停止写入，向前修复。** 可只读安全提示，但不要把“能看到旧截图”称为兼容可玩。原0.7.1或12种关闭包不是可写回滚目标，不恢复旧备份抹掉正常新进度。

## 6. 发布顺序仍成立：同批开放，不降生产门槛做演示

原①→⑦继续：固定真实生产基线/集成→库存基础与关闭包→新鱼/图鉴/迁移→人数→单粒喂养→冻结完整包→一次维护发布。本文件是该顺序的补充，不要求人数先上一天，也不重开售卖24h灰度计时；售卖仍默认off，另按#51已有门槛开放。

门槛矩阵：两水域×内部rod_level 0/1/2/3/4×两新种历史catch 0/1/2/3=160个抽池状态；加保底边界与2→3越界。低等级可见剪影和正确条件、钓不到新种，本身就是PASS；新种首捕/重复/上限及动作，使用**恢复副本/测试站合法构造的Lv.3/4夹具**分别验，不依赖随机等一位真实玩家升级。

不临时降低生产门槛，不向普通玩家发等级/鱼做演示。若需要录屏，可在隔离测试环境用明确标注的测试档；不能把修改过的配置/种子带入最终生产包。生产试跑用管理员指定测试号，若暂无合法达标号，该项标未验，不能写成“全量验证通过”，但不把“所有玩家都能马上钓到新鱼”作为发布目标。
