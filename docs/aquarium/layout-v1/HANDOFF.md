# 装饰纵深／逐件尺寸与重复鱼展示规则

作者：GPT / Codex；原插件 (C) 2026 Carinoasd。日期：2026-10-30。关联 Issue #44，回应 #36 评论 6502553838。

## 一、装饰规格：本次补充的新展示规则

原设只有前后景适配建议，没有逐件深度数值。这份是本轮补充的可实现展示规格，待实际合成校准，不把它写成已存在的原始美术设定。

机器配置：`source/plugin/gamecenter/games/aquarium/assets/layout/decor-layout-v1.json`。24 件逐项对应原美术 manifest 的稳定 ID、源尺寸、可见边界与锚点；原美术 manifest 不修改。完整数值表见 [decor-table.md](decor-table.md)。

- `ground_y_ratio`：接地点从鱼缸内视窗顶部向下的比例，远景约 0.76～0.83、中景 0.83～0.90、近景 0.90～0.96。它不是 CSS bottom，也不是整张透明图片的底边。
- `visible_width_ratio`：实际可见装饰轮廓的宽度／缸宽，**已含推荐深度的透视尺度**。不得再乘一次按类别的 0.9／0.96 等系数；也不能把它直接作为整张透明图的 CSS width。
- `source_visible_bbox / source_size / anchor`：直接沿用当前资源；细高长叶、提灯与宽景桥的透明留白差异很大，必须用可见边界换算。
- `preferred_x / placement_preference`：柔性摆放偏好，均不是硬限制。没有任何一件必须成对；沉眠列柱和羽翼纪念像已经是完整复合图，不拆分、不自动复制。
- `default_layer / allowed_layers`：保留已有后端 back/front 适配。远／中／近是画面纵深，不增加第三份服务端列表，不放宽当前允许层，也不改变容量、购买资格或经济。

`decor-layout.js` 提供纯几何换算：

```js
const r = AquariumDecorLayout.rect(spec, tankWidth, tankHeight, anchorX);
// r.sprite: 整张图片的 left/top/width/height，像素值。
// r.visible: 真正可见轮廓的矩形，用于边界与遮挡判断。
// r.ground: 图内锚点在鱼缸中的位置；r.paintLayer 沿用原 back/front。
```

先根据可见宽度求整图宽度，再保留源图长宽比，最后让图内 anchor 落到指定接地点。当前装饰 anchor 为 [0.5, 0.9]；简单设置 bottom:0 会把这段留白误当作接地点。

同一 paint layer 内按接地点 Y 从远到近绘制；碰撞判断用可见边界，允许小草有少量自然交叠，大型建筑之间保留主体轮廓。位置不够时提示换位或换主景，不暗中缩小成玩具、不裁掉边缘、不改变拥有与容量。

这些数值先作为自动摆放默认值。若要让玩家自由改变深度并跨设备保存，需要单独定义受限位置字段、版本与服务端校验；不能只在前端记住后声称支持永久自由摆放。本批不增加位置存档。

## 二、远景美术：先保留原图，不加一套降饱和变体

本批不用类别统一 saturation(0.82)，也不在母版上烘焙雾色。远景只加上限 8～10% 的场景水色叠层，中景上限 2.5%，近景不加；这是可调上限，不必所有物品都吃满。

采用原 alpha 范围内的场景色覆盖，避免给矩形透明区域上色；日光与月光取各自背景的水色。提灯的暖金、红叶与珊瑚原色保留，发光芯可避开雾层。投影只可用很弱的接地影，避免整张图片黑色描边式 drop-shadow。

只有后续构图确实需要非常远的建筑时，再针对该件制作专属远景变体；目前不增加 24 件×昼夜的一整套资源。

## 三、同种鱼：允许重复，明确改写原先限制

原 `DESIGN-v0.2.md` 的水族馆章节确实规定“每种鱼最多同时展示一条”。小蓝按这条写去重并非擅自加限制。这轮根据用户反馈调整为：

1. 首次发现鱼种，永久解锁展示资格；可在总鱼位容量内放多条相同鱼。初始 4 位、扩到 8/12 的容量规则继续沿用。
2. 重复展示属于布置选择，不生成个体库存，不按累计捕获数量扣鱼，不扣金币；捕获计数仍是历史统计，重复鱼捕获继续按既有规则给金币。
3. `layout.fish` 仍为定长数组，每个非空槽是一条展示实例；允许同一个合法、已发现 ID 重复。装饰的唯一性不变。
4. 渲染实例以槽位（例如 slot-0、slot-1）为键，不能继续用 fish_id 作唯一 Map 键。移动或收回只作用于选定槽位，不一次删掉该鱼种全部展示实例。
5. 同种鱼各自保留位置、初相、转向与速度；同种 atlas 可以共享缓存，但每条鱼有独立宿主与播放器。不要为了展示同种鱼重复加载 8 份贴图。
6. 图鉴显示“已展示 N 条”；提供明确的“再放一条”和对指定实例的收回入口。图鉴发现进度按不同鱼种统计，鱼缸占用按非空槽统计，两者不能混用。

## 四、小蓝实现与验收清单

后端现有 `aquarium_shop.php` 至少两处拒绝重复鱼：`validateState()`，以及 layout 写入分支的目标验证。两处都要调整，保留合法已发现 ID、数组长度、容量、权限、版本冲突等校验；装饰去重不得误删。还需搜索其他唯一性断言与原测试。

同版本连续放两条、重复点击／丢响应重试时，队列操作必须以明确目标槽与目标鱼种表示。旧请求重试不得再找一个新空槽，否则一次点击会多出两条。先确认当前槽位状态，再决定补交或标冲突。

- 8 个展示位放同种鱼：8 个独立可见实例，不重叠锁步、不额外扣币；刷新与重新登录后一致。
- 收回其中一条：只清该槽；图鉴仍已发现，其他七条保留。
- 未发现／未知 ID、超容量、非法长度、旧版本写入仍被拒绝；原合法布置能正常保存。
- 重复提交绝对目标布局／同槽目标，不新增额外实例；两标签冲突后读取最新状态再判断。
- 3 件最大建筑＋近景灯／草、日光／月光、960×600 和窄屏合成：接地、比例、遮挡、热区需实测。

本 PR 仅规格、几何辅助与规则修订，**没有实现服务端重复鱼，也没有接入当前玩家界面**。数值换算通过不等于视觉／实站验收。
