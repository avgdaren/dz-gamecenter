## 1. 一句话介绍与边界

选一个水域自动钓鱼，离开后继续积累收获；回来发现新鱼、升级钓具，把喜欢的鱼放进自己的小小水族馆。

目标是一天打开一两次、每次约 1～3 分钟；隔几天回来仍保留存档，但只补算前24h收益。愿意停留的人可以看鱼、查图鉴、换布置。点击与挂机不额外提高产出。

- 使用论坛账号服务端存档，跨设备继续。
- 没有饥饿、死亡、脏水、维护费、连续签到惩罚。
- 金币仅本游戏使用，不兑换论坛积分。
- 不做繁殖、交易、偷鱼、排行榜、互访、抽卡、付费加速、消耗鱼饵、每日必做或转生。
- “天使”为系列名与轻幻想气质，不引入角色战斗系统。
- 首版是有限内容的数天收集与布置体验，不承诺数周经营深度。买齐后可继续看鱼与存档，金币允许积累。

只读展示页、新水域与新装饰留后续；论坛勋章需另评估配置、发放去重和回滚，不写成已承诺奖励。

## 2. 玩家体验

### 2.1 新玩家

1. 先看到已有水草和灯光的示意水景。
2. 登录且有权限后，点击“建立水族馆”，初始化仅发生一次。
3. 不超过 10 秒的引导演出获得晴蓝鱼，点亮图鉴并放进第一个鱼位。
4. 初始金币 120，另加引导鱼 2 金币；可立即购买 Lv1 鱼竿。
5. 明示“已开始自动钓鱼，关闭页面后也会累计，最多 X 小时”；X 来自最终定案配置。
6. 引导可跳过；刷新/重试不重发奖励。引导鱼不占普通捕获序号和进度，保底初始为 0。

奖励与初始档在一次创建中原子保存，不做“先插行、再补发新手奖励”。

### 2.2 回来之后

先同步结算，再集中展示：离开多久、有效累计多久、金币、捕获数量、新鱼。确认按钮只关闭面板，不再次发奖。多种新鱼合并展示，一键关闭。

玩家可以选新鱼布置，购买一次升级/扩容/装饰，选择继续探索的水域，然后离开。不会推测离线中途的购买意图。

### 2.3 未登录与无权限

- 游客看到明确标注“演示画面”的初始鱼缸、一条游动鱼和图鉴剪影，不获得收益、不创建本地或服务端影子档案。
- 游客卡片：“登录后建立水族馆”；提示：“登录论坛账号后，即可建立并保存自己的水族馆。”
- 已登录无档：“建立水族馆”；已有档：“进入水族馆”。
- 已登录无权限：“当前用户组暂不能建立或操作水族馆。”首版展示演示，不请求本人存档，不显示可购买按钮。
- 建档、会落账的同步和所有写操作均由服务端验证 uid 与 can_play()，不能靠按钮隐藏实现权限。

## 3. 自动钓鱼与鱼种

### 3.1 核心规则

同时一个水域、一条捕获进度。每个周期必得一种鱼并获得固定金币；没有空竿、垃圾、背包上限或手动出售。

首捕永久解锁图鉴及展示资格；重复鱼只加金币和捕获计数。鱼与装饰不额外生产金币，按喜好布置。

在线与离线使用相同规则、概率和保底；界面倒计时不产生已确认收益。

### 3.3 图鉴保底

每个水域独立保存连续无新发现次数：

- 普通捕获发现新鱼则清零，否则加一。
- 捕获前计数已经为 80 且该水域还有未发现鱼时，该次只在未发现集合按原整数权重抽签。
- 因而触发在连续 80 次无新发现后的第 81 条，不是在第 80 条。
- 切水域保留各自计数；集齐后停止累加。引导只解锁晴蓝鱼，不走普通捕获流程。
- 保底不需要先归一成浮点概率，直接累计剩余鱼的原权重；不另掷一个保底骰。

图鉴明示规则和当前计数；首次发现时间按捕获实际完成时刻推导，不能统一填同步请求时间。

## 4. 图鉴与鱼缸

### 4.1 展示鱼

初始 4 位，可扩至 8/12；“选鱼位→选鱼”编辑，不做拖拽编辑器。每种鱼最多同时展示一条；移出不丢资格。已放别处的鱼再次选择时明确提示移动，不静默挤掉其他鱼。

编辑时显示位置；正常观看隐藏边框。位置用于保存归属，动画分前后层、上下漂移，避免每条鱼被锁进可见矩形格子。无碰撞或复杂寻路。

点击可看名字、发现时间和捕获次数，并移出鱼缸。图鉴未发现卡显示名称、剪影、品级、水域、基本概率；发现后显示彩色图和简短介绍，可直接放入鱼缸。

### 4.2 装饰：用途分类与主题标签

用户反馈二次元版概念图“没什么问题，仍有后续打磨空间”，所示装饰数量可以，建议分类。因此以该图的24件规模作为首版内容整理目标；不是将此前“24～30件”的上限30一并视为批准，也不把图中所有缩略图直接当最终制作清单。

**推荐四个用途主分类，每类先按6件编目，共24件。以下名称为策划示例，最终去重、命名和造型另做素材清单：**

| 主分类 | 用途 | 6件示例 |
|---|---|---|
| 水草 | 填充、柔化边缘、营造生机 | 水草丛、睡莲、长叶草、红叶草、水蕨、海藻束 |
| 石景 | 组织地形、形成视觉骨架 | 卵石组、层岩、苔石、沉木、岩洞、珊瑚景 |
| 建筑 | 作为场景主角，明确风格 | 小桥、凉亭、月门、拱门、遗迹石柱、天使门 |
| 摆件 | 小面积点缀和视觉焦点 | 贝壳、珍珠台、星灯、弯月雕塑、水晶簇、羽翼雕像 |

“石景”是石木造景的易懂入口，含沉木、珊瑚等造景主件；人工拱门/石柱归建筑，天然岩洞归石景。复合素材按主体用途只归一个主分类，避免同一素材在不同分类重复计数。

**主题是第二维标签：**自然水景、珊瑚浅湾、月光庭院、遗迹秘境。一个物品有一个主分类、可带多个主题标签；类别回答“找什么”，主题回答“搭什么风格”。同主题可以混搭，不设套装产出加成或强制集齐奖励。

装饰库交互建议：
- 第一行主分类：全部 / 水草 / 石景 / 建筑 / 摆件。
- 主题作为次级筛选，可与类别组合；手机收进筛选面板，避免多排标签占首屏。
- 已拥有 / 未拥有作为状态筛选；已拥有未摆放与已摆放有明确标记，空结果可清除筛选。
- 背景（日光/月光）放在独立的背景入口，不混进24件装饰计数。
- 单件有独立图标、主体轮廓及展示预览；同素材换色不充当另一件，组合图里的小草/碎石也不拆成虚假条目。

**类别不等于摆放层。**每件另标适合前景/后景，供布置和遮挡校验；水草、石景等不是各自只能摆一个的槽位。原“前后景各3位”仍为布局候选，尚未由用户冻结，需以24件库的换装预览确认密度后确定。默认场景底图不占购买物品。

同一装饰最多摆一次，允许留空、移走后保留拥有权。物品分类和主题元数据跟随稳定decor_id放在配置里，不新增数据库分类表，不影响鱼种抽签协议。

装饰只作观赏，不提高钓鱼收益、不收维护费。后续按类型/主题规划逐步可购买的顺序与价格，不一次发完24件；具体门槛在内容数值评审确定。数量增加不能单独证明内容寿命已足够。

## 5. 成长与经济候选

### 5.1 鱼竿：不锁鱼已定，降价仍为候选

用户已确认不限制鱼种。当前方案只提高速度、不改变概率、不锁珍奇鱼；下表价格待试玩和数值评审。价格为“升到该级的单次费用”，不是累计费用。

|---|---:|---:|---:|---:|---:|---:|
| Lv0 | 120s | 初始 | 79.2 | 151.8 | — | — |
| Lv1 | 108s | 120 | 88.0 | 168.7 | 13.6h | 7.1h |
| Lv2 | 96s | 260 | 99.0 | 189.8 | 23.6h | 12.3h |
| Lv3 | 84s | 600 | 113.1 | 216.9 | 42.4h | 22.1h |

升级同时加速金币与发现鱼；仍需复算完整路线，不能因总价接近水域价就宣布“先开水域/先升竿”已均衡。

解锁浅湾不自动切换；进入浅湾收益更高，池塘保留补图鉴用途。接受首版集齐池塘后主要去浅湾，不增加多资源来强造长期钓点竞争。

### 5.2.1 装饰定价原则（用户已确认）

全部价格使用**本游戏内金币**；不使用人民币标价，不兑换论坛积分。购买永久解锁展示资格，移动/换装不重复收费。

| 类别 | 价格层次 | 产品目的 |
|---|---|---|
| 水草 | 低价 | 前期容易买到，能逐步填充和调整鱼缸 |
| 石景 | 低价 | 让玩家较早有条件搭建基础造景 |
| 建筑 | 最高价档 | 作为大幅改变画面的主景和后期攒钱目标 |
| 摆件 | 按美术精细度分档 | 简洁贝壳等便宜，造型/细节更丰富的灯饰、雕塑等逐步提高；建筑保留最高价档 |

这是用户对相对价位的决定，尚未指定每件金额。不将“看起来精细”自动换算成价格或按贴图分辨率收费；策划结合可见细节、轮廓造型与画面表现给每件明确固定金币价，不随机涨价。不同主题不额外收主题费，不加生产收益。

后续形成24件清单时，逐件列出类别、精细度档、金币价、可购买条件和预览。先验证低价水草/石景在前期确实负担得起，再验证建筑攒钱目标不会形成空等；摆件档次需要玩家从图标/预览看得出差异。具体价目与总消费按现有钓鱼收入、鱼竿/水域/扩容的购买竞争重算。

### 5.3 总消费与节奏验证

24件装饰现有[候选清单与价目](DECOR-CATALOG-v0.1.md)。用户已认可四样稿，并确认晴光水草/绮色珊瑚便宜、月庭圆门/星辉提灯昂贵。星辉提灯原600中档价退出当前候选，记作待定T；其他价暂沿候选，则水草1,140+石景1,680+建筑20,700+其他摆件3,980+T=**27,500+T**。加鱼竿1,880+浅湾2,000+扩容3,800=**35,180+T金币**。旧28,100/35,780只对应T=600的历史算术，当前不能沿用；新价需经济模拟/试玩，尚未冻结。

浅湾满级理论产出253金币/h；“总标价÷满级产出”只作静态比较，不能代表从新手开始的解锁/集齐时间。首次金币、升级顺序、回访频率和随机发现都要纳入模拟。

例如引导后Lv1留在池塘离开72h，按已确认24h上限仅累计24h：正常概率下期望捕获收入2,112，非未受限72h的6,336。离线不能自动解锁、升级或切换；此例未计保底和初始余额。

v0.1 的约 22.7/27.0h 解锁模拟不适用于新版价格，**不得沿用为 v0.2 模拟结果**。现已完成明示策略的候选模型，见[经济路线模拟](ECONOMY-SIM-v0.1.md)；仍未真人试玩。

后续至少验证：优先开水域、优先升竿、先买装饰/扩容，以及每天一次/每三天一次回访。记录水域解锁、集齐鱼种、全部升级和全部商品的耗时分布，不只比较满级产量。目标仍是前一分钟有新鱼和首次升级、数天逐步完成收藏；不要用维护惩罚或高价无效升级硬拖寿命。

## 8. 账号存档、结算与冻结协议

本节为应有行为，不代表现成实现。技术讨论已收口，代码仍需按下文验证。

### 8.1 一表与原子操作

1.4.0已有客户端JSON槽位存档，持久化能力并非缺失。水族馆仍选择独立权威表：经济与活动布置都需拥有权、容量、唯一性及版本校验，同档可保持原子一致，不拆进通用三槽存档。平台save/load/delsave契约保留供其他游戏使用。完整理由见[存档与迁移决策](CONFIG-MIGRATION-PLAN.md)。

新增 InnoDB gamecenter_aquarium_save：uid 主键、save_version、config_version、state_json、version、updated_ms。JSON 含金币、等级、水域、图鉴/首次发现时刻、保底、布置、结算锚点/余数、seed_hex、catch_seq、配置池指纹及必要最近摘要。

uid 来自会话。seed 不在任何客户端响应或日志中。客户端不得上传最终金币、时间、随机结果或整档覆盖。

初始化并发用唯一键收口，奖励在初始 JSON 内创建；重复读取实际存在档。数据库错误不能一概当“已存在”，读取/迁移失败不能删旧档重建。

操作同账号串行：锁行→检查 expected_version→按旧状态结算→条件校验→明确目标操作→同事务保存。成功变化推进 version；旧版本冲突返回最新状态。若购买失败但结算已产生收益，允许仅提交结算并明确购买未发生。

购买携带 target_rod_level、目标容量或 item_id 等绝对意图；旧请求重试不得换新版本变成新的相对操作。不设 action/request_id 表，不保证逐字恢复旧响应；重连读取最新状态。不能透支、重复收费、超等级或越权布置。

使用 DB::begin_transaction()/commit()/rollback()，RETRY/unbuffered 及有限死锁/锁超时重试；提交前失败不推进锚点，提交后响应丢失不重复买。锁后取时间，重试时重读状态。同步也会落账，应受权限与写入保护。

### 8.2 整数毫秒与离线上限

设保存锚点 L、锁后当前时间 N、余数 p、周期 D、上限 C，均为整数毫秒，0≤p<D：

- t=min(max(N-L,0),C)
- k=intdiv(p+t,D)
- p_new=(p+t)%D
- 按顺序处理 k 条捕获，保存余数与 L_new=max(L,N)。

**用户已定 C=86400000（24h）**，意图为提高活跃度；是否确实改善活跃度需上线观察，不写成已验证效果。初始化前、帮助和收益摘要均明示上限与超时部分不累计。这是产品节奏选择，不是PHP性能必需。

只计算离开后的前 C 时长，超出时间永久舍弃；锚点仍推进到 N。刷新不领取被舍弃部分；时钟回退不倒退锚点、不重复发奖。

该批第 j 条捕获（j 从1起）完成时刻为 L+(D-p)+(j-1)×D。首次发现以此时刻保存，不填请求到达时间。不跨配置自动切段。

### 8.3 升级、切换和配置维护

先结算旧周期，升级余数用 intdiv(old_p×new_D,old_D)。每次损失小于1ms，最多4次；不引入第二套刻度。切水域保留同周期余数，下一次捕获使用新水域。解锁不自动切换。

首版冻结经济配置。config_version 未支持或指纹不匹配，拒绝结算、保留原档并报配置错误。未来改数另设计维护窗口：阻止新写入、排空在途事务、备份、旧规则结算到统一切点、迁移并验证后开放。

不做运行时跨版本分段；不是取消迁移义务。CREATE TABLE IF NOT EXISTS 不补列；新增列或 JSON 语义变化需相应兼容/迁移，失败不覆盖旧档。配置变化必须有归档旧配置、统一切点、旧规则结算、row/JSON同事务转版本、dry-run/断点恢复与备份回退；详见[迁移预案](CONFIG-MIGRATION-PLAN.md)。该预案不是已实现工具，正式上线前必须完成工具及真实库验证。本轮24h已定，不迁到72h。

### 8.4 aquarium-rng-v1

- 初始化 random_bytes(16)，以32位小写 seed_hex 存档；计算前严格解码成16原始字节。
- catch_seq 初始0。下一条 n=catch_seq+1，成功保存后 catch_seq=n；引导不占序号。
- 每条 draw_index 初始0；消息严格十进制 ASCII uid:n:draw_index，无前导零、空格、换行，等价 sprintf('%d:%d:%d',uid,n,draw_index)。
- HMAC-SHA256 的 key 为原始 seed 字节，message 为上述 ASCII；取摘要前4字节为无符号大端 x。目标 PHP 为64位环境。
- 有效权重总和 W 为1..2^31整数；limit=intdiv(4294967296,W)×W。x≥limit 时 draw_index++ 重算，接受后 ticket=x%W。
- 先决定正常/保底候选表，再按 §8.5 排序累计整数权重，选择累计和首次大于 ticket 的鱼。普通/保底不另掷骰；不得用 mt_rand、当前时间或请求批次影响序列。
- 相同初始状态、配置和操作时间线，在没有丢弃时间差异时，分批与整批得到相同捕获序列。

### 8.5 显式排序与配置指纹（最终评审新增硬约束）

首版鱼种可直接在静态配置内，不因此新增鱼表。无论配置来源，water_id/fish_id 仅限小写 ASCII 字母、数字、下划线且首位字母；ID 唯一。抽签候选按 fish_id 的 ASCII 字节升序排序，使用明确字节比较，不依赖数据库默认 collation 或容器插入顺序。

如以后从数据库读取，必须显式 ORDER BY fish_id ASC，仍在 PHP 按同一 ASCII 规则验证/规范化；SQL 排序不替代协议的字节顺序。保底先筛选未发现集合，再沿用同一顺序，不能因差集操作改变列表。

冻结配置包含“各水域排序后的 fish_id+原始整数权重”与 RNG 协议。概率池指纹规范：

1. 所有水域按 water_id ASCII 升序，每个水域鱼按 fish_id ASCII 升序。
2. 规范化文本以 ASCII aquarium-pools-v1 加 LF 开头；随后每鱼一行 water_id、TAB、fish_id、TAB、十进制weight、LF，无额外空格、无前导零。
3. 对完整 UTF-8/ASCII 字节求 SHA-256 小写十六进制，作为 pool_hash。
4. 每个 config_version 的预期 pool_hash 写在受评审冻结清单；存档记录其值。运行时从实际配置重算并与冻结清单/存档校验，不能把“实际算出的值”同时当作新的预期值而绕过检查。
5. 金币、周期、价格、上限等同属 config_version 冻结内容；pool_hash 专门覆盖抽签列表，不虚称它校验了全部经济字段。首个正式 hash 要在配置冻结时生成并交叉复算，本版不捏造生产 hash。

原始配置返回顺序改变，经规范化仍为同一列表时不影响结果；实际排序后的列表/权重改变而版本未更新必须拒绝结算。加载后应使用同一份经过验证的不可变列表累计权重，防止“哈希用排序表、抽签用原数组”。

### 8.6 settle 纯函数与外层职责

settle(array $save,int $now_ms,array $config):array 返回规则状态 save 与本次 catches；每条含 fish_id、coins、is_new，必要时附完成时刻。

不得读 HTTP、DB、$_G、系统时间或外部随机；时间/种子/配置由入参提供。外层负责权限、事务、版本、响应、持久化。最终规则状态与拼接 catches 可做批次等价比较；外层 version、逐批摘要不要求相等。

### 12.1 玩家、权限与存档

- 1分钟内首鱼与首次升级；初始化竞争/刷新不重复发奖。
- 游客演示无收益无建档，无权限/伪造uid/金币/时间/鱼种被拒，正常操作不误判。
- 手机约360px宽可完成核心操作；状态和品级不只靠颜色。
- 鱼/装饰校验拥有权、层/槽位、数量、唯一性；移出不丢资格。
- 装饰主分类互斥且完整覆盖独立物品；主题筛选可组合，拥有/摆放标记正确；分类不误用作放置层或槽位上限，切换筛选不改变已保存布置。
- 价目表全部为本游戏金币，水草/石景低价、建筑占最高价档、摆件有可解释的精细度分档；服务端按配置扣款，客户端不能篡改价格。永久解锁后反复换装不再收费。
- 换设备、退出重登保持；账号切换不显示上一账号缓存。
- 新鱼集中展示、关闭摘要不发奖；超过上限提前说明。
- 集齐后可继续观看/布置，无失效强制任务；减少动态和隐藏暂停生效。

### 12.2 纯函数与边界

相同输入两次逐字段一致。在未触发不同时间丢弃的相同时间线：
- 一次24h与24次1h：最终规则状态、拼接catches、首次发现时刻、catch_seq、余数、保底相同。
- 正式上限为24h：一次72h离开只算前24h；72次1h因中途同步可累计72h，两者预期不同。
- 外层行version、请求时间、每批摘要不是等价对象。

每类至少6个固定用例，下表为最小覆盖，不是已通过结果：

| 类别 | 六个边界 |
|---|---|
| 升级 | 余数0；余数D-1；恰到捕获；跨多个周期后升级；floor换算非整除；Lv4拒绝再升 |
| 切水域 | 余数0；余数D-1；恰到捕获先归旧水域；往返保留余数；未解锁拒绝；两域独立保底 |
| 上限丢弃 | C-1；C；C+1；2C只算C；立即重同步无补领；带余数跨C后锚点正确 |
| 时钟回退 | N=L；N=L-1；大幅回退；回退后仍低于L；恢复到L；超过L后仅结新增 |

保底另验79/80边界、第81条、提前自然发现清零、集齐停计数、水域独立。上限场景中“一次离开很久”与“中途回来多次”可有不同收益，不错误要求分批等价。

### 12.4 排序/哈希

- 打乱原始配置插入顺序，归一后pool_hash和落鱼不变。
- 若走DB，测试返回逆序/不同读取顺序，显式排序后相同。
- 普通池与保底子集均按ASCII fish_id排序，不能对中文名、品级或展示位置排序。
- 修改一个fish_id、权重或有效鱼集合而不更新冻结清单，拒绝结算；存档锚点/金币保持。
- hash验证后抽签只能使用同一份规范化列表；构造原数组/排序数组不同顺序的反例。
- 非法/重复ID、零负权重、空池、溢出权重均明确报配置错。集齐保底不用空的未发现池，而应正常抽全池。

### 12.5 并发、故障和接入

- 两标签/两进程同时结算不双发，初始化竞争仅一档。
- 同版本同时购买最多一笔成功，不能透支/超级/重复收费；目标和旧version重发不再购买。
- 服务端提交成功丢响应后恢复最新档；客户端不自动改新version续买。
- 提交前后故障、死锁/锁超时重试、驱动重连防护分别验证；无未处理死锁，有限重试耗尽返回可恢复错误。
- 配置指纹错、未知版本、损坏JSON/迁移失败保留原档不重置；备份恢复可继续结算。
- 缺formhash、错HTTP方法、错gkey/op、手工start/submit/board/rank不能旁路。
- 旧游戏、公共SDK、积分/榜单和后台回归；两种驱动/querysafe是否实测逐项写明。

### 12.6 性能与交付证据

不以“PHP应当毫秒级”代替性能结果。按最终上限与最高等级测批量结算时间、锁占用、请求载荷和并发，性能阈值在实现任务结合实际站点容量先确定。证据必须含SHA/环境/命令或步骤/预期实际/未验项。

纯函数、隔离数据库、DOM/模拟与真实Discuz分别标注；未测即未验证。文档本身只验证一致性和覆盖范围。
